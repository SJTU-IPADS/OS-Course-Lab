## 寄存器

`mcpu` 中的寄存器是一个数组 `R[18]`：

| 下标                                                           | 寄存器                                                             |
| -------------------------------------------------------------- | ------------------------------------------------------------------ |
| `RAX`、`RCX`、`RDX`、`RBX`、`RSP`、`RBP`、`RSI`、`RDI`（0..7） | 通用寄存器，编号与机器码中的编号相同                               |
| `R8` .. `R15`（8..15）                                         | 通用寄存器，编号需要 REX 前缀的一位                                |
| `RFLAGS`（16）                                                 | 标志寄存器，本机器只使用 CF、PF、ZF、SF、OF 五位与恒为 1 的第 1 位 |
| `RIP`（17）                                                    | 指令指针                                                           |

`interp.c` 中定义了 `#define R c->R`，因此 `R[RSP] -= 8`、`R[RIP] += rel` 这样的语句直接修改寄存器。`c->r[RAX]`、`c->rflags`、`c->rip` 是同一数组的另一种写法，框架的其他文件使用这种写法。

向量寄存器是另一个数组 `Y[16]`（`#define Y c->Y`），即 ymm0..ymm15，每个 256 位，类型为 `u256`：

```c
typedef union { uint64_t q[4]; uint32_t d[8]; uint8_t b[32]; } u256;
```

`Y[n].d[i]` 是第 i 个 32 位的通道（lane），`d[0]`..`d[3]` 组成 xmm n。本实验的向量指令只做 32 位整数运算。

## 第一部分：`modrm.c`

`modrm_decode(p, n, rex, &m)` 从 `p` 处可读的 `n` 个字节中解析 ModRM 字节 `p[0]`，以及随后的 SIB 字节与位移（如果有），填写 `modrm_t m` 的全部字段，返回用掉的字节数（1 到 6）；`n` 个字节在操作数结束之前用完时返回 0。`rex` 是指令的 REX 前缀，没有时为 0：第 2 位是 REX.R，第 1 位 REX.X，第 0 位 REX.B。它只读字节，不访问寄存器与内存。第三讲“指令的字节表示”一页说明指令以操作码开头、其后是长度可变的操作数字段；ModRM、SIB 与 REX 的全部规则在下面三小节与 `modrm.c` 的注释中。

| 字段            | 含义                                                                      |
| --------------- | ------------------------------------------------------------------------- |
| `mod`           | ModRM 的 mod 字段（0..3）                                                 |
| `sub`           | reg 字段本身（0..7）；组指令用它扩展操作码                                |
| `reg`           | reg 字段加上 REX.R 作为第 3 位（0..15）                                   |
| `rm`            | `mod` 为 3 时是 rm 字段加上 REX.B 作为第 3 位（0..15）；内存操作数时为 -1 |
| `base`、`index` | 内存操作数的基址与变址寄存器编号 0..15，没有时为 -1                       |
| `scale`         | 1、2、4、8；没有变址时为 1                                                |
| `rip`           | 1 表示相对于下一条指令的地址                                              |
| `dsize`、`disp` | 位移的字节数（0、1、4）与符号扩展后的值                                   |

内存操作数的地址是 `disp + base + index * scale`，`rip` 为 1 时是 `disp` 加下一条指令的地址。`mod` 为 3 时 `base`、`index` 为 -1，`scale` 为 1，`rip`、`dsize`、`disp` 为 0。

### ModRM 字节

```
ModRM   位 7 6    5 4 3    2 1 0
           mod    reg      rm
```

`mod` 不为 `11` 时另一个操作数在内存中，`rm` 字段是基址寄存器，有两个例外：

- `rm` 为 `100`：随后有一个 SIB 字节，基址与变址由它给出；
- `rm` 为 `101` 且 `mod` 为 `00`：没有基址，随后是 4 字节位移，地址相对于下一条指令（`%rip`）。

两个例外只看 3 位的字段，不看 REX.B：有 REX.B 时 `rm` 为 `100` 仍然带 SIB 字节（`%r12` 作基址需要它），`rm` 为 `101` 且 `mod` 为 `00` 仍然是 `%rip` 相对寻址。

### SIB 字节

```
SIB     位 7 6    5 4 3    2 1 0
           scale  index    base
```

1. `scale` 为 0、1、2、3 时比例因子为 1、2、4、8；
2. `index` 加上 REX.X 作为第 3 位；得到 4（`index` 为 `100` 且没有 REX.X）表示没有变址，有 REX.X 时是 `%r12`；
3. `base` 加上 REX.B 作为第 3 位；`base` 字段为 `101` 且 `mod` 为 `00` 时没有基址，`base` 保持 -1，随后是 4 字节位移。判断只看 3 位的字段，因此 REX.B 为 1 时（`%r13`）同样没有基址。

VEX 前缀中的 R、X、B 位已经由调用者换算成 `rex` 的对应位，`modrm_decode` 不需要区分两种前缀。

### 位移

位移紧跟在 ModRM 字节（有 SIB 字节时在 SIB 之后）之后，字节数由 `mod` 决定：

| `mod` | 位移                                                                |
| ----- | ------------------------------------------------------------------- |
| `00`  | 没有；`base` 为 -1（`%rip` 相对寻址，或 SIB 字节没有基址）时 4 字节 |
| `01`  | 1 字节                                                              |
| `10`  | 4 字节                                                              |

位移是小端的，`disp` 是符号扩展到 64 位的值。反汇编器在 `dsize` 不为 0 时打印位移，因此 `8b 45 00` 打印为 `mov 0x0(%rbp),%eax`，`dsize` 必须为 1。

| ModRM 起的字节      | `rex` | 操作数             | `m` 的字段                      |
| ------------------- | ----- | ------------------ | ------------------------------- |
| `c3`                | 0     | `%ebx`（`mod` 11） | `rm` 3                          |
| `00`                | 0     | `(%rax)`           | `base` 0                        |
| `40 f8`             | 0     | `-0x8(%rax)`       | `base` 0，`dsize` 1，`disp` -8  |
| `45 00`             | 0     | `0x0(%rbp)`        | `base` 5，`dsize` 1，`disp` 0   |
| `80 00 01 00 00`    | 0     | `0x100(%rax)`      | `base` 0，`dsize` 4             |
| `05 10 00 00 00`    | 0     | `0x10(%rip)`       | `rip` 1，`dsize` 4，`disp` 0x10 |
| `04 8b`             | 0     | `(%rbx,%rcx,4)`    | `base` 3，`index` 1，`scale` 4  |
| `04 24`             | 0     | `(%rsp)`           | `base` 4，没有变址              |
| `04 20`             | 0x42  | `(%rax,%r12,1)`    | `base` 0，`index` 12，`scale` 1 |
| `04 c5 10 00 00 00` | 0     | `0x10(,%rax,8)`    | 没有基址，`index` 0，`scale` 8  |

## 第二部分：`alu.c`

`alu.c` 中的函数计算一次整数运算的结果，并只修改 `*f` 的五个标志位，其余的位保持不变：

| 标志 | 位  | 含义                                                                           |
| ---- | --- | ------------------------------------------------------------------------------ |
| CF   | 0   | 加法向最高位之外进位，减法向最高位借位，即无符号数的结果超出 `size` 字节       |
| PF   | 2   | 结果的低 8 位中 1 的个数为偶数                                                 |
| ZF   | 6   | 结果的低 `size` 字节为 0                                                       |
| SF   | 7   | 结果的最高位（第 `size * 8 - 1` 位）                                           |
| OF   | 11  | 有符号数的结果超出 `size` 字节：两个最高位相同的数相加，结果的最高位与它们不同 |

`size` 是操作数的字节数（1、2、4、8）。`mcpu.h` 提供五个辅助函数：`trunc_val(v, size)` 截断到 `size` 字节，`sext(v, size)` 把 `size` 字节的 `v` 符号扩展为 `int64_t`，`msb(size)` 是最高位的掩码，`parity(v)` 判断低 8 位的奇偶，`flag(f, m, on)` 设置或清除 `f` 中的位 `m`。

十个函数分为三组，后面的函数调用前面的函数：

| 组                  | 函数                                         | 调用的函数                                                                  |
| ------------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| 加、减与逻辑运算    | `x86_szp`、`x86_logic`、`x86_add`、`x86_sub` | 后三个用 `x86_szp` 设置 ZF、SF、PF                                          |
| `inc`、`dec`、`neg` | `x86_inc`、`x86_dec`、`x86_neg`              | `x86_add`、`x86_sub`，各调用一次                                            |
| 移位、乘法与除法    | `x86_shift`、`x86_mul`、`x86_div`            | 前两个自己计算 CF、OF，用 `x86_szp` 设置 ZF、SF、PF；`x86_div` 不改变标志位 |

其中 `x86_add`、`x86_inc`、`x86_div` 三个函数与 `x86_shift` 中 `shl`、`sal` 的分支（`switch` 的 `default`）已经写出。你写其余六个函数与 `x86_shift` 中 `shr`、`sar` 的两个 `case`：`x86_sub` 的结构与 `x86_add` 相同，CF 与 OF 的条件不同；`x86_dec` 的结构与 `x86_inc` 相同；`shr`、`sar` 的两个 `case` 与 `default` 一样算出 `cf`、`r`、`of`，三者的值见“移位”一节的表。`x86_add` 与 `x86_inc` 调用 `x86_szp`，因此 `x86_szp` 完成之前它们也会打印 `x86_szp is not implemented yet`。

### 加、减与逻辑运算

| 函数                             | 作用                                                                                                                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x86_szp(f, r, size)`            | 返回按结果 `r` 设置了 ZF、SF、PF 的 `f`。`r` 的高位可能不为 0，ZF 与 SF 只看低 `size` 字节，PF 只看低 8 位                                                                       |
| `x86_add(f, a, b, size, carry)`  | `a + b + carry`，返回截断到 `size` 字节的结果，设置五个标志位。`a`、`b` 先截断。`adc` 的结果等于 `a` 时也可能有进位：8 位时 `0x12 + 0xff + 1 = 0x112`，低 8 位为 `0x12`，CF 为 1 |
| `x86_sub(f, a, b, size, borrow)` | `a - b - borrow`，同上。CF 为无符号数的 `a < b + borrow`；`borrow` 为 1 且 `b` 全为 1 时 `b + borrow` 自身会回绕                                                                 |
| `x86_logic(f, r, size)`          | `and`、`or`、`xor`、`test` 的结果 `r`：返回截断后的 `r`，按它设置 ZF、SF、PF，清零 CF、OF                                                                                        |

`size` 为 1 时的例子：

| 运算          | 结果   | 标志        |
| ------------- | ------ | ----------- |
| `0xff + 0x01` | `0x00` | CF ZF PF    |
| `0x7f + 0x01` | `0x80` | SF OF       |
| `0x80 + 0x80` | `0x00` | CF ZF PF OF |
| `0x00 - 0x01` | `0xff` | CF SF PF    |
| `0x80 - 0x01` | `0x7f` | OF          |

### `inc`、`dec`、`neg`

| 函数                  | 作用                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `x86_inc(f, v, size)` | `v + 1`。ZF、SF、PF、OF 与 `x86_add(f, v, 1, size, 0)` 相同，CF 保持调用前的值             |
| `x86_dec(f, v, size)` | `v - 1`。ZF、SF、PF、OF 与 `x86_sub(f, v, 1, size, 0)` 相同，CF 保持调用前的值             |
| `x86_neg(f, v, size)` | `0 - v`。结果与五个标志位都与 `x86_sub(f, 0, v, size, 0)` 相同，因此 `v` 不为 0 时 CF 为 1 |

这三个函数各调用一次 `x86_add` 或 `x86_sub`。`x86_inc` 与 `x86_dec` 在调用之前记下 `*f` 中的 CF，调用之后把它写回。

`size` 为 1 时的例子：

| 运算       | 结果   | 标志           |
| ---------- | ------ | -------------- |
| `inc 0xff` | `0x00` | ZF PF，CF 不变 |
| `inc 0x7f` | `0x80` | SF OF，CF 不变 |
| `dec 0x00` | `0xff` | SF PF，CF 不变 |
| `neg 0x01` | `0xff` | CF SF PF       |
| `neg 0x80` | `0x80` | CF SF OF       |

### 移位

`x86_shift(f, sub, v, n, size)` 把 `v` 移动 `n` 位，返回截断到 `size` 字节的结果。`sub` 是指令 ModRM 的 reg 字段：4 为 `shl`，5 为 `shr`，6 为 `sal`（与 `shl` 相同），7 为 `sar`。

移位的位数只取 `n` 的低位：`size` 为 8 时取低 6 位，其余取低 5 位，因此 1 字节与 2 字节的操作数最多移动 31 位。取低位之后位数为 0 时，函数返回截断后的 `v`，不改变任何标志位。位数不为 0 时，ZF、SF、PF 由结果设置，CF 与 OF 如下：

| 运算         | 结果                      | CF                                                                        | OF                           |
| ------------ | ------------------------- | ------------------------------------------------------------------------- | ---------------------------- |
| `shl`、`sal` | 左移，低位补 0            | 最后移出的一位，即 `v` 的第 `size * 8 - n` 位；`n` 大于操作数的位数时为 0 | 结果的最高位与 CF 不同时为 1 |
| `shr`        | 右移，高位补 0            | 最后移出的一位，即截断后的 `v` 的第 `n - 1` 位                            | `v` 的最高位                 |
| `sar`        | 右移，高位补 `v` 的最高位 | 符号扩展后的 `v` 的第 `n - 1` 位                                          | 0                            |

x86 只在移动 1 位时定义 OF，只在位数小于操作数的位数时定义 `shl` 与 `shr` 的 CF。本机器的提交日志记录标志位，因此任何位数都按上表计算。循环移位 `rol`、`ror` 由框架的 `x86_rotate`（`frame/arith.c`）计算。

`size` 为 1 时的例子：

| 运算             | 结果   | 标志     |
| ---------------- | ------ | -------- |
| `shl 0x81`，1 位 | `0x02` | CF OF    |
| `shl 0xc0`，1 位 | `0x80` | CF SF    |
| `shr 0x81`，1 位 | `0x40` | CF OF    |
| `sar 0x81`，1 位 | `0xc0` | CF SF PF |
| `sar 0x81`，9 位 | `0xff` | CF SF PF |
| `shl 0x01`，9 位 | `0x00` | ZF PF    |

### 乘法与除法

`x86_mul(f, sub, a, b, size, lo, hi)` 把 `a` 与 `b` 的低 `size` 字节相乘。乘积有 `2 * size` 字节：低 `size` 字节写入 `*lo`，高 `size` 字节写入 `*hi`，二者都截断到 `size` 字节。`sub` 为 4 时是 `mul`（两个操作数是无符号数），为 5 时是 `imul`（有符号数）；二操作数与三操作数格式的 `imul` 也以 5 调用，只使用 `*lo`。

| 标志       | 设置                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| CF、OF     | 乘积超出 `size` 字节时都为 1，否则都为 0。`mul`：`*hi` 不为 0；`imul`：乘积不等于 `*lo` 符号扩展得到的值 |
| ZF、SF、PF | 由 `*lo` 设置。x86 没有定义乘法之后的这三个标志位，本机器的提交日志记录标志位，因此规定为 `*lo` 的结果   |

`x86_div(sub, hi, lo, v, size, q, r)` 做除法。被除数有 `2 * size` 字节，高 `size` 字节在 `hi` 中，低 `size` 字节在 `lo` 中；除数是 `v` 的低 `size` 字节。`sub` 为 6 时是 `div`（无符号数），为 7 时是 `idiv`（有符号数：商向 0 取整，余数的符号与被除数相同）。函数把商写入 `*q`、余数写入 `*r`（都截断到 `size` 字节）并返回 0；`v` 为 0 或商超出 `size` 字节时返回 -1，框架据此报告 `fault (divide error)`。除法不改变标志位，因此没有参数 `f`。

`size` 为 8 时乘积与被除数有 128 位。`gcc` 提供 128 位的整数类型 `unsigned __int128` 与 `__int128`，运算的写法与其他整数类型相同：

```c
unsigned __int128 p = (unsigned __int128)a * b;     /* the full product of two 64-bit numbers */
uint64_t lo = (uint64_t)p, hi = (uint64_t)(p >> 64);
```

有符号除法在比被除数更宽的类型中计算：`int64_t` 的最小值除以 -1 在 C 中同样溢出，本机 CPU 报告除法错误，`mini-unit` 收到信号 8。`size` 为 8 时没有更宽的类型，被除数为 -2^127、除数为 -1 的这一种情况在做除法之前返回 -1。

`size` 为 1 时的例子：

| 运算                                                    | 结果                               | 标志        |
| ------------------------------------------------------- | ---------------------------------- | ----------- |
| `mul`：`0x10 × 0x10 = 0x0100`                           | `lo` 为 `0x00`，`hi` 为 `0x01`     | CF OF ZF PF |
| `mul`：`0xff × 0x01 = 0x00ff`                           | `lo` 为 `0xff`，`hi` 为 `0x00`     | SF PF       |
| `imul`：`0xff × 0x01 = 0xffff`（-1 × 1 = -1）           | `lo` 为 `0xff`，`hi` 为 `0xff`     | SF PF       |
| `imul`：`0x40 × 0x02 = 0x0080`（128 超出 8 位有符号数） | `lo` 为 `0x80`，`hi` 为 `0x00`     | CF OF SF    |
| `div`：`0x0107 ÷ 0x10`                                  | 商 `0x10`，余数 `0x07`             | 不变        |
| `div`：`0x0100 ÷ 0x01`                                  | 返回 -1：商 `0x100` 超出 8 位      | 不变        |
| `idiv`：`0xfff9 ÷ 0x02`（-7 ÷ 2）                       | 商 `0xfd`（-3），余数 `0xff`（-1） | 不变        |
| `idiv`：`0xff80 ÷ 0xff`（-128 ÷ -1）                    | 返回 -1：商 128 超出 8 位有符号数  | 不变        |

### 调用这些函数的代码

前四个函数由框架的 `x86_alu(f, aop, a, b, size)`（`frame/arith.c`）按运算编号（0 add，1 or，2 adc，3 sbb，4 and，5 sub，6 xor，7 cmp）调用，返回结果并更新标志位；cmp 返回 `a - b`，调用者不写回。解释器的 `case` 调用的是 `x86_alu`，见第三部分。

其余六个函数由框架的 `x86_other`（`frame/x86rest.c`）调用：它取出 `inc`、`dec`（`fe`/`ff`）、`neg`、`mul`、`imul`、`div`、`idiv`（`f6`/`f7`）、`imul`（`0f af`、`69`、`6b`）与移位（`c0`/`c1`/`d0`..`d3`）的操作数，调用对应的函数，再写回结果。你的 `interp.c` 不需要为这些指令写 `case`。`not` 不改变标志位，由 `x86_other` 直接按位取反。

## 第三部分：`interp.c` 的整数指令

这一部分完成 `cond` 与 `interp_run` 中整数指令的 `case`。主循环与四个整数指令的 `case` 已经写出；向量指令的 `case` 留到第四部分；这一部分完成后，除 `simd`、`tinytf` 与 `mini-ollama-simd` 外的客户机程序都能正确运行。

### `cond`

`cond(f, cc)` 按条件码 `cc` 的低 4 位判断标志 `f` 是否满足条件，返回 1 或 0。只看低 4 位，因此你可以直接传入 `jcc` 的操作码。16 种条件列在 `mcpu.h` 与 `interp.c` 的注释中。

### 主循环

`interp_run(c)` 的主循环已经写在 `interp.c` 中。它每次循环执行一条指令，直到客户机退出或发生异常，或者 `--max` 给出的指令数已经执行（`opt_max`，`mcpu.h` 中声明的选项变量，为 0 时不限）：

```c
x86 x;
while (!c->halted && !(opt_max && c->icount >= opt_max)) {
    unsigned op = x86_begin(c, &x);
    switch (op) {
    case 0x81: case 0x83: ...
    default: x86_other(&x); break;
    }
    if (x86_end(&x) < 0)
        break;
}
```

| 步骤               | 作用                                                                                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x86_begin(c, &x)` | 保存全部寄存器，供 `x86_end` 在异常时恢复；从 `R[RIP]` 取最多 15 个字节；跳过前缀，记录 REX 与操作数大小；读出操作码并返回。返回时 `R[RIP]` 指向操作码之后的字节 |
| `switch (op)`      | 用 `fetch8`、`fetch32`、`modrm` 等读出指令的其余部分，`R[RIP]` 随之前进，读完时 `R[RIP]` 就是下一条指令的地址；然后计算并写寄存器与内存                          |
| `x86_end(&x)`      | 没有异常时指令数加一并写提交日志；有异常时把寄存器恢复为指令开始前的值，返回 -1                                                                                  |

操作码是一个字节时 `op` 就是这个字节；以 `0f` 开头的两字节操作码返回 `0x100 | 第二个字节`，例如 `0f 84`（位移为 4 字节的 `je`）为 `0x184`，`syscall`（`0f 05`）为 `0x105`。

跳转指令的位移相对于下一条指令的地址。位移读出之后 `R[RIP]` 已经指向下一条指令，因此你把跳转写成 `R[RIP] += rel`。

### 一条指令的字节

第三讲“指令的字节表示”一页说明：指令以操作码开头，其后是长度可变的操作数字段。`objdump -d` 在每条指令的左边打印它的字节，这些字节从左到右最多分为四段：

| 段                 | 内容                                                                                   | 读它的代码                                  |
| ------------------ | -------------------------------------------------------------------------------------- | ------------------------------------------- |
| 前缀               | `66` 与 REX（`40`..`4f` 中的一个字节），各自可以没有                                   | `x86_begin`，结果在 `x.size` 与 `x.rex` 中  |
| 操作码             | 1 个字节，或 `0f` 加 1 个字节                                                          | `x86_begin`，返回值是 `op`                  |
| 操作数字节         | 第一部分的 ModRM 字节，以及随后的 SIB 字节与内存操作数的位移，共 1 到 6 字节；可以没有 | `modrm(&x)`                                 |
| 立即数或跳转的位移 | 1、2、4 或 8 字节的常数；可以没有                                                      | `fetch8`、`fetch32`、`fetch64`、`fetch_imm` |

进入 `case` 时前两段已经读过，`R[RIP]` 指向第三段的第一个字节。后两段有没有、各占几个字节由操作码决定，因此每个 `case` 开头读指令的调用是固定的。下表把十一条指令的字节分到四段中，`push` 与 `movq` 三条来自 block，其余来自 hello：

| `objdump -d` 打印的汇编        | 前缀 | 操作码  | 操作数字节          | 立即数或跳转的位移 |
| ------------------------------ | ---- | ------- | ------------------- | ------------------ |
| `ret`                          |      | `c3`    |                     |                    |
| `push %rbp`                    |      | `55`    |                     |                    |
| `push %r12`                    | `41` | `54`    |                     |                    |
| `mov %eax,%edi`                |      | `89`    | `c7`                |                    |
| `mov %rax,%rdi`                | `48` | `89`    | `c7`                |                    |
| `mov (%rsp),%rdi`              | `48` | `8b`    | `3c 24`             |                    |
| `and $0xfffffffffffffff0,%rsp` | `48` | `83`    | `e4`                | `f0`               |
| `movq $0x0,0x403020(,%rsi,8)`  | `48` | `c7`    | `04 f5 20 30 40 00` | `00 00 00 00`      |
| `mov $0x402000,%esi`           |      | `be`    |                     | `00 20 40 00`      |
| `jne 401110`                   |      | `75`    |                     | `f3`               |
| `js 4010e2`                    |      | `0f 88` |                     | `96 00 00 00`      |

从这张表可以读出三件事：

- 前缀 `48` 表示操作数是 64 位的，`x.size` 为 8；没有前缀时 `x.size` 为 4。`get`、`set`、`rm_get`、`rm_set` 按 `x.size` 读写，所以 `mov %eax,%edi` 与 `mov %rax,%rdi` 由同一个 `case 0x89` 执行。
- 一个助记符可以对应几个操作码：表中的 `mov` 有 `89`、`8b`、`c7`、`be` 四个，它们的操作数种类不同，后两段的组成也不同。
- 有的操作码把寄存器编号的低 3 位放在自己的低 3 位中：`55` 是 `push %rbp`（编号 5），`be` 是写入 `%esi`（编号 6）。编号的第 3 位在前缀的最低位，`41 54` 是 `push %r12`（编号 12）。

### `struct x86` 中解释器读取的字段

| 字段               | 含义                                                                                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `c`                | 当前机器                                                                                                                                                |
| `pc`               | 指令的地址                                                                                                                                              |
| `op`               | 操作码，同 `x86_begin` 的返回值                                                                                                                         |
| `size`             | 操作数大小（字节）：默认 4，REX.W 为 8，前缀 `66` 为 2；8 位指令由 `x86_other` 设为 1                                                                   |
| `rex`              | REX 前缀字节，没有时为 0。`push`、`pop` 与操作码为 `b8`..`bf` 的 `mov` 把寄存器编号的低 3 位放在操作码中，寄存器编号为 `(op & 7) \| ((x.rex & 1) << 3)` |
| `reg`              | `modrm` 读出的寄存器操作数编号（0..15），已经加上 REX 的一位                                                                                            |
| `sub`              | ModRM 的 reg 字段本身（0..7）。操作码 `81`、`83` 用它选择运算                                                                                           |
| `rm`               | rm 操作数是寄存器时为其编号，是内存时为 -1                                                                                                              |
| `vex`、`v`、`vlen` | 向量指令的字段，见第四部分                                                                                                                              |
| 其余字段           | 由辅助函数使用：指令字节、保存的寄存器、内存地址、写内存的记录                                                                                          |

### 辅助函数

以下函数声明在 `mcpu.h`，第一个参数都是 `&x`。读写向量操作数的三个函数见第四部分。

| 函数                                      | 作用                                                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `fetch8`、`fetch16`、`fetch32`、`fetch64` | 从 `R[RIP]` 读 1、2、4、8 字节（小端），`R[RIP]` 前进。返回无符号值，你需要符号扩展时写 `(int8_t)fetch8(&x)` |
| `fetch_imm`                               | 读操作数大小的立即数：`size` 为 1 时 1 字节，为 2 时 2 字节，否则 4 字节；符号扩展到 64 位                   |
| `modrm`                                   | 调用 `modrm_decode` 读 ModRM 字节以及随后的 SIB 与位移，填写 `reg`、`sub`、`rm`，用寄存器的值算出内存地址    |
| `get(&x, n)`、`set(&x, n, v)`             | 按 `size` 读写寄存器 `n`。`size` 为 4 时 `set` 把高 32 位清零，为 1、2 时保留其余的位，与 x86-64 的规则一致  |
| `rm_get`、`rm_set`                        | 读写 rm 操作数：寄存器时调用 `get`、`set`，内存时在 `ea` 处读写 `size` 字节                                  |
| `ea`                                      | 内存操作数的地址。rip 相对寻址的地址在调用时加上 `R[RIP]`                                                    |
| `load(&x, a, n)`、`store(&x, a, n, v)`    | 在地址 `a` 读写 `n` 字节。访问失败时记录缺页，`load` 返回 0，`store` 不写                                    |

计算结果与标志位时，你用第二部分的 `x86_alu(f, aop, a, b, size)`，`f` 是标志寄存器的地址，一般写 `&R[RFLAGS]`；条件跳转用 `cond(R[RFLAGS], op)`。`alu.c` 的其余六个函数（`x86_inc` 到 `x86_div`）由 `x86_other` 调用，你的 `case` 不需要它们。

### `interp_run`

`interp.c` 中已经写出四个整数指令的 `case`：带立即数的八种运算（`0x81` 与 `0x83`）、`push`（`0x50`..`0x57`）与两种 `jmp`（`0xeb` 与 `0xe9`）。`interp_run` 开头的注释另给出 `mov`（`0x89`）的写法。你新增指令时可以参照它们：

```c
case 0x89:                                  /* mov: rm = reg */
    modrm(&x);
    rm_set(&x, get(&x, x.reg));
    break;

case 0x81: case 0x83:                       /* rm = rm OP imm */
    modrm(&x);
    v = op == 0x83 ? (uint64_t)(int64_t)(int8_t)fetch8(&x) : fetch_imm(&x);
    v = x86_alu(&R[RFLAGS], x.sub, rm_get(&x), v, x.size);
    if (x.sub != 7)
        rm_set(&x, v);
    break;
```

整数指令按操作码之后还有哪些字节分为五组，已经写出的 `case` 在“做的事”一列中注明，其余的由你写。各表中“例子”一列是 `objdump -d` 打印的字节与汇编，最后一列是 `guest/` 下首先执行到这条指令的程序（顺序为 hello、sum、matmul、heap、pattern、block、deep）。

**第一组：只有操作码。** `case` 中没有读指令的调用。`push` 与 `pop` 的寄存器编号是 `(op & 7) | ((x.rex & 1) << 3)`。

| `op`           | 指令   | 做的事                                     | 例子                                    | 首先用到 |
| -------------- | ------ | ------------------------------------------ | --------------------------------------- | -------- |
| `0x50`..`0x57` | `push` | `R[RSP]` 减 8，新的栈顶 = 寄存器；已经写出 | `55`：`push %rbp`；`41 54`：`push %r12` | block    |
| `0x58`..`0x5f` | `pop`  | 寄存器 = 栈顶的 8 字节，`R[RSP]` 加 8      | `5d`：`pop %rbp`；`41 5c`：`pop %r12`   | block    |
| `0xc3`         | `ret`  | `R[RIP]` = 栈顶的 8 字节，`R[RSP]` 加 8    | `c3`：`ret`                             | hello    |

**第二组：操作码之后是操作数字节。** `case` 的第一句是 `modrm(&x)`。操作数字节给出两个操作数：reg 是编号为 `x.reg` 的寄存器，用 `get(&x, x.reg)`、`set(&x, x.reg, v)` 读写；rm 是一个寄存器或一处内存，用 `rm_get(&x)`、`rm_set(&x, v)` 读写。两个操作数中哪一个是目标由操作码决定：`mov %rax,%rdi` 的操作码是 `89`，目标是 rm；`mov (%rsp),%rdi` 的操作码是 `8b`，目标是 reg。内存操作数只能是 rm，所以寄存器写入内存用 `89`，内存读入寄存器用 `8b`。

| `op`                                                           | 指令                                                  | 做的事                             | 例子                                                   | 首先用到 |
| -------------------------------------------------------------- | ----------------------------------------------------- | ---------------------------------- | ------------------------------------------------------ | -------- |
| `0x89`                                                         | `mov`                                                 | rm = reg，上面的 `case`            | `48 89 c7`：`mov %rax,%rdi`                            | hello    |
| `0x8b`                                                         | `mov`                                                 | reg = rm                           | `48 8b 3c 24`：`mov (%rsp),%rdi`                       | hello    |
| `0x8d`                                                         | `lea`                                                 | reg = rm 的地址，即 `ea(&x)`       | `48 8d 74 24 08`：`lea 0x8(%rsp),%rsi`                 | hello    |
| `0x01`、`0x09`、`0x11`、`0x19`、`0x21`、`0x29`、`0x31`、`0x39` | `add`、`or`、`adc`、`sbb`、`and`、`sub`、`xor`、`cmp` | rm = rm 运算 reg                   | `48 29 c2`：`sub %rax,%rdx`                            | hello    |
| `0x03`、`0x0b`、`0x13`、`0x1b`、`0x23`、`0x2b`、`0x33`、`0x3b` | 同上八种                                              | reg = reg 运算 rm                  | `4c 03 04 d5 20 30 40 00`：`add 0x403020(,%rdx,8),%r8` | matmul   |
| `0x85`                                                         | `test`                                                | 按 rm & reg 设置标志位，不写操作数 | `48 85 ff`：`test %rdi,%rdi`                           | hello    |

这两行各有八个操作码，从左到右依次是 add、or、adc、sbb、and、sub、xor、cmp，运算编号（0 到 7）是 `op >> 3`：`0x29 >> 3` 为 5，所以 `48 29 c2` 是 sub。结果与标志位由 `x86_alu(&R[RFLAGS], 运算编号, a, b, x.size)` 计算，`a` 是目标操作数原来的值，`b` 是另一个操作数；`test` 的标志位由 `x86_logic` 计算。

**第三组：操作码之后是操作数字节，再是立即数。** `case` 先调用 `modrm(&x)`，再读立即数，最后才调用 `rm_get`、`rm_set`。这一组的指令只有 rm 一个操作数。操作数字节中 reg 的三位在 `0x81` 与 `0x83` 中存放运算编号，值在 `x.sub` 中；在 `0xc7` 中为 0。

| `op`   | 指令           | 读立即数的调用                    | 做的事                                            | 例子                                                                 | 首先用到 |
| ------ | -------------- | --------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------- | -------- |
| `0xc7` | `mov`          | `fetch_imm(&x)`                   | rm = 立即数                                       | `48 c7 04 f5 20 30 40 00 00 00 00 00`：`movq $0x0,0x403020(,%rsi,8)` | block    |
| `0x81` | 上面的八种运算 | `fetch_imm(&x)`                   | rm = rm 运算 立即数，运算编号是 `x.sub`；已经写出 | `48 81 ec 08 04 00 00`：`sub $0x408,%rsp`                            | deep     |
| `0x83` | 上面的八种运算 | `(int8_t)fetch8(&x)`，总是 1 字节 | 同 `0x81`；已经写出                               | `48 83 e4 f0`：`and $0xfffffffffffffff0,%rsp`                        | hello    |

`48 83 e4 f0` 的操作数字节 `e4` 是二进制 `11 100 100`：中间三位是 4，运算是 and；最后三位是 4，rm 是 `%rsp`。立即数 `f0` 符号扩展为 -16，`objdump` 把它写作 `0xfffffffffffffff0`。

**第四组：操作码之后是立即数。** 寄存器编号的算法与 `push` 相同。立即数的字节数等于操作数大小，8 字节的形式 `objdump` 写作 `movabs`。

| `op`           | 指令  | 读立即数的调用                                       | 做的事          | 例子                                                                                                       | 首先用到 |
| -------------- | ----- | ---------------------------------------------------- | --------------- | ---------------------------------------------------------------------------------------------------------- | -------- |
| `0xb8`..`0xbf` | `mov` | `x.size` 为 8 时 `fetch64(&x)`，否则 `fetch_imm(&x)` | 寄存器 = 立即数 | `be 00 20 40 00`：`mov $0x402000,%esi`；`48 ba cd cc cc cc cc cc cc cc`：`movabs $0xcccccccccccccccd,%rdx` | hello    |

**第五组：操作码之后是跳转的位移。** 位移 `rel` 是有符号数：1 字节的写 `(int8_t)fetch8(&x)`，4 字节的写 `(int32_t)fetch32(&x)`。读完之后 `R[RIP]` 是下一条指令的地址，跳转就是 `R[RIP] += rel`。`objdump` 打印的是算出的目标地址，例子中写出指令自己的地址。

| `op`             | 指令                                | 位移   | 做的事                                        | 例子                                         | 首先用到 |
| ---------------- | ----------------------------------- | ------ | --------------------------------------------- | -------------------------------------------- | -------- |
| `0xe8`           | `call`                              | 4 字节 | 压入 `R[RIP]`，然后 `R[RIP] += rel`           | 40100d 处的 `e8 e9 00 00 00`：`call 4010fb`  | hello    |
| `0xeb`           | `jmp`                               | 1 字节 | `R[RIP] += rel`；已经写出                     | 401107 处的 `eb 0b`：`jmp 401114`            | hello    |
| `0xe9`           | `jmp`                               | 4 字节 | `R[RIP] += rel`；已经写出                     | 4011be 处的 `e9 d2 00 00 00`：`jmp 401295`   | block    |
| `0x70`..`0x7f`   | `jo`、`jno`、`jb` 等十六种条件跳转  | 1 字节 | `cond(R[RFLAGS], op)` 为 1 时 `R[RIP] += rel` | 40111b 处的 `75 f3`：`jne 401110`            | hello    |
| `0x180`..`0x18f` | 同上十六种，字节是 `0f 80`..`0f 8f` | 4 字节 | 同上                                          | 401046 处的 `0f 88 96 00 00 00`：`js 4010e2` | hello    |

`e8 e9 00 00 00` 在地址 40100d，长 5 字节，下一条指令在 401012；`rel` 为 `0xe9`，目标是 `401012 + 0xe9`，即 4010fb。`75 f3` 在 40111b，下一条指令在 40111d；`rel` 为 `(int8_t)0xf3`，即 -13，目标是 401110。条件跳转的操作码的低 4 位是条件码，`cond` 只看这 4 位：`0x75` 与 `0x185` 都是条件 5（ne）。

你需要注意的规则：

- 立即数与位移按 `fetch_imm` 或 `(int8_t)`、`(int32_t)` 做符号扩展。`0x83` 的立即数总是 1 字节，`0x81` 与 `0xc7` 的立即数用 `fetch_imm`。
- 先读立即数，再调用 `rm_get`、`rm_set` 或 `ea`。rip 相对寻址的地址是 `R[RIP]` 加位移，`R[RIP]` 必须已经越过整条指令。
- cmp（运算 7）只更新标志位，不写回操作数。
- `pop %rsp` 的结果是读出的值：先读栈，再把 `R[RSP]` 加 8，最后写目标寄存器。
- `call` 压入的返回地址是下一条指令的地址，即读完位移之后的 `R[RIP]`。
- 一个 `case` 可以在 `store` 之前修改寄存器。`load` 或 `store` 失败时，`x86_end` 恢复指令开始前的全部寄存器，包括 `Y[]`。

### 交给 `x86_other` 的指令

`switch` 的 `default` 把其余操作码交给框架的 `x86_other`，它执行：8 位与 al/eax 立即数形式的算术逻辑运算（`00`、`02`、`04`、`05` 等）、`80`、`84`、`88`、`8a`、`b0`..`b7`、`c6`，`movsxd`（`63`）、`movzx`/`movsx`（`0f b6`/`b7`/`be`/`bf`）、`cmovcc`、`setcc`，`imul`（`0f af`、`69`、`6b`）、组 3（`f6`/`f7`：`test`、`not`、`neg`、`mul`、`imul`、`div`、`idiv`）、移位（`c0`/`c1`/`d0`..`d3`），`cltq`/`cqto`（`98`/`99`）、`test al/eax, imm`（`a8`/`a9`）、`xchg`（`87`）、`push imm`（`68`/`6a`）、`leave`（`c9`）、组 4、5（`fe`/`ff`：`inc`、`dec`、`call *`、`jmp *`、`push`）、`nop`、`endbr64` 与多字节 `nop`、`pushfq`、`popfq`、`syscall`。`x86_other` 遇到本部分的表与第四部分的表中的操作码时报告非法指令。其中 `inc`、`dec`、`neg`、`mul`、`imul`、`div`、`idiv` 与 `shl`、`shr`、`sal`、`sar` 的结果和标志位由你的 `alu.c` 计算，见第二部分“调用这些函数的代码”。

`x86_other` 还执行 `guest/ollama/` 用到的浮点指令与另外三条向量指令，运算写在 `frame/simd.c` 中：

| 指令                                                            | 内容                                                                                                               |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `movss`、`movups`、`movaps`、`movdqa`、`movdqu`、`movd`、`movq` | xmm 寄存器与内存、通用寄存器之间的传送                                                                             |
| `addss`、`subss`、`mulss`、`divss`、`sqrtss`、`minss`、`maxss`  | 单精度浮点数的运算，结果舍入到最近的可表示值                                                                       |
| `cvtsi2ss`、`cvttss2si`                                         | 整数转为单精度浮点数；单精度浮点数截去小数部分转为整数                                                             |
| `ucomiss`、`comiss`                                             | 比较两个单精度浮点数，结果写入 ZF、PF、CF                                                                          |
| `andps`、`andnps`、`orps`、`xorps`、`pxor`                      | 128 位的按位运算                                                                                                   |
| `vpmovzxbd`、`vpand`、`vpsrld`                                  | `guest/ollama/dot_q4.s` 取出 4 位权重用的三条 AVX2 指令：8 个字节零扩展为 8 个 32 位通道，按位与，每个通道逻辑右移 |

前五行是 SSE 指令：操作码为 `0f` 加一个字节，`op` 是 `0x100` 加这个字节，同一个 `op` 的几条指令由前缀 `66`、`f3` 区分（`0f 58` 带 `f3` 是 `addss`），`x86_begin` 把前缀记在 `x.pp` 中。它们读写 xmm 寄存器，即 `Y[n]` 的低 128 位，高 128 位保持不变。这些指令的 `op` 与你的 `case` 不重合，你的 `switch` 不需要为它们做任何事。

## 第四部分：`interp.c` 的向量指令

七条向量指令中 `vphaddd` 与 `vextracti128` 的 `case` 已经写出，这一部分在 `switch` 中增加其余五条的 `case`。增加之前，这五条指令进入 `default`，`x86_other` 报告非法指令：`./mini-cpu guest/simd` 打印 `scalar = -28`，执行 660 条指令之后在 `linear_simd` 的第一条向量指令 `vpxor`（地址 401222）处停止。

### 操作码与字段

以 VEX 前缀（`c4` 或 `c5`）开头的指令，`x86_begin` 解析前缀并返回 `0x1000 | map << 8 | 操作码字节`，map 为 1、2、3 时分别对应 `0f`、`0f 38`、`0f 3a`。例如 `c4 e2 7d 40 c1`（`vpmulld %ymm1,%ymm0,%ymm0`）的 map 为 2、操作码字节为 `40`，`op` 为 `0x1240`。VEX 编码的指令不在本实验子集内时，`x86_begin` 直接报告非法指令。VEX 前缀是 `c5` 加 1 个字节，或 `c4` 加 2 个字节；它之后依次是 1 个操作码字节、操作数字节与立即数，`case` 读后两段的方式与整数指令相同。

| 字段   | 含义                                                                 |
| ------ | -------------------------------------------------------------------- |
| `vex`  | 指令带 VEX 前缀                                                      |
| `v`    | VEX.vvvv 指定的向量寄存器编号（0..15），三操作数指令的第一个源操作数 |
| `vlen` | 向量宽度（字节）：VEX.L 为 0 时 16（xmm），为 1 时 32（ymm）         |

`x.reg` 与 `x.rm` 在向量指令中是向量寄存器的编号，`modrm` 照常读出 ModRM、SIB 与位移。

### 辅助函数

| 函数                   | 作用                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------- |
| `rm_vget(&x, &v, n)`   | 读向量 rm 操作数的 `n` 字节到 `v`：寄存器时取 `Y[rm]`，内存时在 `ea` 处读；`n` 以上的字节为 0                  |
| `rm_vset(&x, &v, n)`   | 写向量 rm 操作数的 `n` 字节：寄存器时调用 `vset`，内存时在 `ea` 处写                                           |
| `vset(&x, n, &v, len)` | `Y[n]` 的低 `len` 字节设为 `v`，其余字节清零。VEX 编码的指令写 xmm 时清零 ymm 的高半部分，与 x86-64 的规则一致 |

### 七条指令

`interp_run` 开头的注释给出 `vpxor` 的写法；已经写出的 `vphaddd` 与 `vextracti128` 两个 `case` 也可以参照：

```c
case 0x11ef:                                /* vpxor: reg = v ^ rm */
    modrm(&x);
    rm_vget(&x, &b, x.vlen);
    for (int i = 0; i < 4; ++i)
        r.q[i] = Y[x.v].q[i] ^ b.q[i];
    vset(&x, x.reg, &r, x.vlen);
    break;
```

`b` 与 `r` 是 `u256` 类型的局部变量。

七条向量指令都出现在 `guest/linear.s` 的 `linear_simd` 中，`guest/simd` 与 `guest/tinytf` 调用它；`tests/lab1/vecops.py` 生成的程序以随机的操作数使用这七条指令。reg、v、rm 分别是 `x.reg`、`x.v` 与 rm 操作数：

| `op`     | 指令           | 语义                                                                                                      | 例子                                                 |
| -------- | -------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| `0x11ef` | `vpxor`        | reg = v ^ rm，见上面的例子                                                                                | `c5 ed ef d2`：`vpxor %ymm2,%ymm2,%ymm2`             |
| `0x116f` | `vmovdqu`      | reg = rm，宽度 `vlen`；rm 可以是内存                                                                      | `c4 a1 7e 6f 04 87`：`vmovdqu (%rdi,%r8,4),%ymm0`    |
| `0x11fe` | `vpaddd`       | reg = v + rm，按 32 位通道逐个相加，共 `vlen / 4` 个通道                                                  | `c5 ed fe d0`：`vpaddd %ymm0,%ymm2,%ymm2`            |
| `0x1240` | `vpmulld`      | reg = v × rm，每个通道保留乘积的低 32 位                                                                  | `c4 e2 7d 40 c1`：`vpmulld %ymm1,%ymm0,%ymm0`        |
| `0x1202` | `vphaddd`      | 只有 xmm 形式：reg 的四个通道依次为 v0+v1、v2+v3、rm0+rm1、rm2+rm3；已经写出                              | `c4 e2 69 02 d2`：`vphaddd %xmm2,%xmm2,%xmm2`        |
| `0x1339` | `vextracti128` | 8 位立即数的最低位为 0 时取 ymm reg 的低 128 位，为 1 时取高 128 位，写入 xmm rm 或 16 字节内存；已经写出 | `c4 e3 7d 39 d1 01`：`vextracti128 $0x1,%ymm2,%xmm1` |
| `0x117e` | `vmovd`        | rm（32 位的寄存器或内存）= xmm reg 的通道 0，用 `rm_set` 写入                                             | `c4 c1 79 7e d1`：`vmovd %xmm2,%r9d`                 |

例子是 `linear_simd` 中的指令。三个操作数在 `objdump` 的写法中依次是 rm、v、reg：`vpaddd %ymm0,%ymm2,%ymm2` 的 rm 是 `%ymm0`，v 与 reg 都是 `%ymm2`。`vextracti128` 与 `vmovd` 的目标是 rm：`c4 e3 7d 39 d1 01` 的操作码字节是 `39`，操作数字节是 `d1`，立即数是 `01`，reg 是 `%ymm2`，rm 是 `%xmm1`。

`linear_simd` 中这些指令的地址：`vpxor` 401222，`vmovdqu` 401232、401238，`vpmulld` 40123e，`vpaddd` 401243、401253，`vextracti128` 40124d，`vphaddd` 401257、40125c，`vmovd` 401261。

你需要注意的规则：

- 向量运算先把结果算到局部的 `u256` 中，再用 `vset` 或 `rm_vset` 写出：`vpaddd %ymm0,%ymm2,%ymm2` 这样的指令，目标同时是源操作数。
- `vextracti128` 的立即数在 ModRM 与位移之后，要在 `rm_vset` 之前读出，与整数指令先读立即数的规则相同。

其余五条完成后，`guest/simd`、`guest/tinytf` 与 `guest/mini-ollama-simd` 能够正确运行。`guest/mini-ollama-simd` 的 `dot_q4`（`guest/ollama/dot_q4.s`）使用其中的 `vpmulld`、`vpaddd`、`vextracti128`、`vphaddd`、`vmovd` 五条，另外三条 `vpmovzxbd`、`vpand`、`vpsrld` 由 `x86_other` 执行。

## 第五部分：在解释器上运行真实模型

这一部分不计分，没有要写的代码，`make check` 不运行它。前四部分完成后，你就可以用自己的解释器运行 `guest/mini-ollama-simd` 与真实的模型，再把同一个程序直接在本机运行，比较两次运行的用时。

两次运行装入同一个可执行文件，执行同一批指令：

- **直接运行。** `gcc` 编译出的机器指令由本机的 CPU 执行，这种方式称为编译执行。
- **在解释器上运行。** `interp_run` 的每次循环读入一条指令，由解释器的代码修改 `R`、`Y` 与客户机的内存，这种方式称为解释执行。

### 模型文件

真实模型是 Hands-on 实验 `nano-quant` 以 `--recipe q4_0` 生成的 `q4_0.gguf`，也就是 ollama 装载的那个文件。如果你在 `nano-quant` 中已经得到 `q4_0.gguf` ，可以直接使用它，否则可以从下面的云盘链接里下载：

<https://pan.sjtu.edu.cn/web/share/a853ce437a176a0064df9a5af1942ecf>

本部分通过设置环境变量 `MODEL` 指向模型文件，使 mini-ollama 程序能够读取它：

```bash
export MODEL=path/to/q4_0.gguf
```

### 直接运行

`guest/mini-ollama-simd` 的系统调用与 Linux 的编号、参数相同，因此这个文件可以直接在本机运行。请先直接运行一次，确认模型文件可用：

```bash
time guest/mini-ollama-simd "用一句话介绍你自己。" < "$MODEL"
```

```
我是一个虚拟助手，没有实体，但我可以用文字与你交流，为你提供帮助和解答。
prompt tokens:    13
generated tokens: 22
logits checksum:  1680878985

real	0m10.610s
user	0m10.573s
sys	0m0.034s
```

这句话也是 ollama 对同一个提示词的回答。`time` 打印的 `real` 一行是这次运行的用时；本节的用时都在一台 i9-11900H 的机器上测得，你的机器上的数值与它不同。直接运行 `guest/mini-ollama-simd` 要求本机 CPU 支持 AVX2；不支持时，本节的直接运行请改为使用 `guest/mini-ollama-ref`。它把 `dot_q4` 换成 C 函数，不含向量指令，打印的文字与三行同 `guest/mini-ollama-simd` 相同；它执行的指令更多，在助教的电脑上完整的回答用 25.6 秒，第一个 token 用 8.6 秒。在解释器上仍运行 `guest/mini-ollama-simd`：它的向量指令由你的代码执行，与本机 CPU 是否支持 AVX2 无关。

### 在解释器上运行

第二个参数 1 使程序生成第一个 token 之后结束。提示词的 13 个 token 先逐个通过模型的 28 层，这段时间程序没有输出，在助教的电脑上执行参考实现的解释器，第 27 分钟打印第一个字：

generated tokens: 1

### 两次运行的比较

你再直接运行一次只生成第一个 token 的命令，与解释器上的那一次比较：

```bash
time guest/mini-ollama-simd "用一句话介绍你自己。" 1 < "$MODEL"
```

|                | 直接运行                                 | 在解释器上运行                   |
| -------------- | ---------------------------------------- | -------------------------------- |
| 执行的指令     | `guest/mini-ollama-simd` 的 241 亿条指令 | 同一批指令，`--stats` 的 `insns` |
| 用时（`real`） | 3.6 秒                                   | 26 分 32 秒                      |
| 每秒执行的指令 | 约 66 亿条                               | 约 1500 万条                     |

在这台机器上，解释执行的用时是直接运行的约 440 倍。你在自己的机器上测出这三行的数值。直接运行改用 `guest/mini-ollama-ref` 时，两次运行执行的指令不同，只比较用时。

用时的差别来自一条指令的执行方式。直接运行时，取出指令、识别操作码、计算内存地址、读写内存与设置标志位都由 CPU 的电路完成。在解释器上，这些步骤各由一段 C 代码完成，每一段都是本机的若干条指令：

| 步骤                                                           | 解释器中完成它的代码     |
| -------------------------------------------------------------- | ------------------------ |
| 保存寄存器，按 RIP 取出指令的字节，读出前缀与操作码            | `x86_begin`              |
| 按操作码找到这条指令的代码                                     | `interp_run` 的 `switch` |
| 从操作数字节算出寄存器编号与内存地址                           | `modrm`、`modrm_decode`  |
| 读写客户机的内存，先查出这个地址在物理内存 `dram.img` 中的位置 | `mem_read`、`mem_write`  |
| 算出结果与全部标志位                                           | `alu.c`                  |
| 计数，检查异常，写提交日志                                     | `x86_end`                |

以小模型的一次运行为例：`./mini-cpu guest/mini-ollama-simd "hello" 8 < guest/tiny.gguf` 执行客户机的 4173393 条指令，参考实现的解释器为此执行约 28 亿条本机指令（`valgrind --tool=cachegrind --cache-sim=no` 的统计），平均每条客户机指令约 670 条，其中一半在 `x86_begin` 中。同一个程序直接运行时，本机 CPU 执行的就是这 417 万条指令。

解释器在每两条指令之间取得控制：`-v`、`--commit`、`--max` 与异常时的寄存器打印都在这个位置进行，客户机的程序不需要任何改动。

```bash

```
fault (illegal instruction) after 0 instructions:
...
rip  0000000000401000  flags -----
```

你用 `objdump -d guest/hello` 查看该地址处的指令：

第三部分完成后的输出：

| 选项            | 作用                                                     |
| --------------- | -------------------------------------------------------- |

| `--commit FILE` | 提交日志，`-` 表示 stdout                                |
| `--max N`       | 执行 N 条指令后停止                                      |
| `--stats`       | 结束时打印指令数、系统调用数与退出码                     |

00401004  op 8d  rax=0                rsp=7fffffffefc0 rdi=1
00401009  op 83  rax=0                rsp=7fffffffefc0 rdi=1

提交日志每条指令一行：指令地址，写入的内存（如有），再依次是与上一行相比值发生变化的寄存器，全部为十六进制，不含 rip。`./mini-cpu --commit a.txt guest/hello` 之后 `a.txt` 的前几行：

```

401004 rsi=7fffffffefc8
401009 flags=6
40100d m[7fffffffefb8]=401012 rsp=7fffffffefb8
4010fb
4010ff r8=1
```

`401009` 处是 `and $0xfffffffffffffff0,%rsp`，rsp 本来已经对齐，值没有变化，因此只有 `flags` 出现。`4010fb` 处是 `endbr64`，不改变任何寄存器。

向量寄存器写作一个 256 位的十六进制数，省略前导的 0，最右边 8 位是通道 0。`./mini-cpu --commit a.txt guest/simd` 中第一次循环的两条指令：

```
401232 ymm0=fffffffd00000003000000020000000100000000fffffffffffffffefffffffd
401238 ymm1=f0000000d0000000b0000000900000007000000050000000300000001
```

`ymm0` 的八个通道从右往左是 `w[0..7]`，即 -3、-2、-1、0、1、2、3、-3；`ymm1` 是 `x[0..7]`，即 1、3、5、…、15。

异常时的寄存器打印在通用寄存器之后列出非零的向量寄存器，每个分成四个 64 位，高位在前。例如第四部分中你的 `switch` 漏掉 `vpmulld` 时：

...
rip  000000000040123e  flags -----

```

### 单独检查一个函数

`make` 同时生成 `mini-unit`（`tests/unit.c`），它不运行客户机程序，直接以固定的参数调用一个文件中的函数，把返回值与留在内存中的结果与 `mcpu.h` 的要求比较，因此 `interp_run` 完成之前你就可以检查 `modrm_decode` 与 `alu.c`：

```bash
./mini-unit modrm          # modrm_decode：每一种形式，以及字节不足的每一种长度
./mini-unit alu            # x86_szp、x86_logic、x86_add、x86_sub、x86_inc、x86_dec、x86_neg
./mini-unit shift          # x86_shift：四种移位，0 到 255 的每一个位数
./mini-unit muldiv         # x86_mul、x86_div
./mini-unit cond           # cond：16 个条件码在 32 种标志组合下
```

每个失败的检查打印一行，说明参数、期望值与实际值（最多 12 行），最后一行是 `组名: N checks, M failed`；没有失败时退出状态为 0。例如你的 `x86_logic` 没有清除 OF 时：

```
alu: x86_logic(f = 0x827604c726055fa6, r = 0x25ceafed65927a90, size 1): flags expected 0x827604c7260557a6, got 0x827604c726055fa6 (CF and OF cleared, ZF SF PF from r)
...
alu: 809792 checks, 400 failed
```

函数尚未完成时打印 `x86_szp is not implemented yet`，以状态 3 退出。每一组按上面注释中的顺序检查各函数，在第一个尚未完成的函数处结束。被检查的函数使程序收到信号时（例如 `x86_div` 中除以零），`mini-unit` 打印信号的编号与这一次调用的参数。

### 生成的程序

除“评测”一节中的 `memops.py` 与 `flagops.py` 外，`tests/lab1/` 中还有三个生成客户机程序的脚本，都用 `gcc -nostdlib -no-pie` 汇编：

| 脚本                     | 程序的内容                                                                                                                                                                                                                    | 期望值                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `condops.py`             | 16 个条件码在 CF、PF、ZF、SF、OF 的 32 种组合下各运行 `setcc`、`cmovcc`、1 字节位移的 `jcc` 与 4 字节位移的 `jcc`，每一对写出 4 个 32 位数                                                                                    | 同一程序在本机 CPU 上的输出                   |
| `randops.py 种子 [块数]` | 每块若干条随机的 `interp.c` 中的整数指令（`mov`、`lea`、八种 ALU 运算、`test`、`push`、`pop`、`call`、`ret`、`jmp`、`jcc`，16、32、64 位，寄存器、立即数与各种形式的内存操作数），每块之后写出 11 个寄存器与 `rflags & 0x8c5` | 同上                                          |
| `vecops.py 种子 [块数]`  | 每块若干条随机的向量指令（上表七条，xmm 与 ymm，寄存器与内存操作数），每块之后写出两个向量寄存器与一次 `vmovd` 的结果                                                                                                         | `vecops.py --want 种子 块数` 在 Python 中计算 |

输出不同时，`--explain` 说明第一处不同的记录；例如：

```bash
python3 tests/lab1/randops.py 5 60 > r.s && gcc -nostdlib -no-pie -o r r.s
./r > want; ./mini-cpu r > got
python3 tests/lab1/randops.py --explain 5 60 want got
```

先打印这一块之后值不同的寄存器，再打印这一块的指令：

```
block 3 of randops.py 5 60 (the registers were equal before it):
  rcx   expected 0x0000000000000000, got 0x0000000000000001
  the instructions of the block:
    orq %rbx,%rax
    adcl $0,%r10d
    ...
```

`condops.py --explain want got` 打印条件码、输入标志与四条指令中出错的一条，`vecops.py --explain 种子 块数 got` 打印值不同的向量寄存器的八个通道与这一块的指令。
