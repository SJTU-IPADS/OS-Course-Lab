# solve-bomb

你得到一个可执行文件 `bomb`，没有源码。程序有 8 个阶段，每个阶段读取一行输入：
输入正确，这个阶段被拆除，程序进入下一个阶段；输入错误，程序显示爆炸并退出。
你要阅读 `bomb` 的机器代码，推出每个阶段接受的输入。

每个学号对应一个 `bomb`，各同学的 `bomb` 接受的输入不同。`bomb` 运行时与课程服务器保持连接，
每一次爆炸、每一个被拆除的阶段都记在你的学号下。

本实验不计分。

本实验配合第三讲「程序的机器级表示」，8 个阶段依次用到讲义中的这些内容：

| 阶段 | 内容 |
| --- | --- |
| 1 | 操作数、内存中的数据 |
| 2 | 标志位、有符号与无符号比较 |
| 3 | 循环、栈上的数组、用栈传递的参数 |
| 4 | 跳转表与间接跳转 |
| 5 | 递归 |
| 6 | 参数与返回值的传递方式 |
| 7 | 位运算、字符的编码 |
| 8 | 位段的拆分、通过指针调用函数 |

本目录中有三个文件：

| 文件 | 内容 |
| --- | --- |
| `Makefile` | 从课程服务器取得你的 `bomb` |
| `bomb-light` | 课堂演示用的程序 |
| `README.md` | 本文 |

## 取得你的 bomb

```bash
make bomb ID=525xxxxxxxxx
```

`ID` 处写你自己的学号。这条命令把学号发给课程服务器，服务器生成这个学号的 `bomb` 并传回，
保存为当前目录下的文件 `bomb`。命令需要 `curl` 或 `wget`，以及到课程服务器的网络连接。

同一个学号每次得到的 `bomb` 相同。文件丢失或换了一台机器时，再执行一次这条命令。

`bomb` 的输入框上方显示它所属的学号（`ID 525xxxxxxxxx`）。开始之前核对这个学号。

`bomb` 在 x86-64 的 Linux 上运行，例如 tut 课「汇编实验准备」中建立的 ubuntu 容器。
它是静态链接的程序，不需要安装任何库。你需要的工具是 `objdump` 与 `gdb`。

## 运行

```bash
./bomb
```

程序启动时连接课程服务器，连接成功之后占据整个终端窗口：上部显示当前的阶段，下部是输入框。
在框中输入一行，按 Enter 提交；`Ctrl-C` 清空这一行，`Ctrl-D` 退出。输入错误时，爆炸的画面显示在窗口中央，随后程序退出。

已经得到的答案可以写在一个文本文件中，每行一个阶段：

```bash
./bomb answers.txt
```

程序先依次读取文件中的行，文件读完之后再从键盘读取。空行被跳过。

输出接到管道或文件时，程序每个阶段输出一行，8 个阶段全部拆除后再输出一行 `All phases are defused.`：

```bash
./bomb answers.txt | cat
```

```
phase 1 of 8 defused
phase 2 of 8 defused
phase 3 of 8 exploded
```

你的学号与规则（`bomb: ID 525xxxxxxxxx`、`bomb: 8 phases. One line defuses a phase. A wrong line sets the bomb off.`）输出在标准错误上，不进入管道。

程序的退出状态：

| 退出状态 | 含义 |
| --- | --- |
| 0 | 8 个阶段全部拆除 |
| 1 | 某个阶段爆炸 |
| 2 | 输入提前结束，或命令行有误 |
| 3 | 连接不上课程服务器，或连接中断 |

加上 `-q`，程序不输出任何内容，结果只在退出状态中：

```bash
./bomb -q answers.txt; echo $?
```

`./bomb -h` 输出一行用法。

### 计分板

```bash
./bomb -s
```

显示全体的计分板：每个 `bomb` 一行，依次是名次、`bomb` 的编号、已拆除的阶段数、爆炸的总次数，以及 8 个阶段各自的爆炸次数。
已拆除的阶段，它的次数显示为绿色。你自己的一行以 `>` 标出；表格之下的一行给出 `bomb` 的总数与你所在的行。

计分板上不显示学号。`bomb` 的编号是 8 位十六进制数字，由服务器从学号算出，从编号不能得到学号。

| 按键 | 作用 |
| --- | --- |
| `↑`、`↓` | 上移、下移一行 |
| `←`、`→`（或 `PgUp`、`PgDn`） | 上一页、下一页 |
| `Home`、`End` | 第一页、最后一页 |
| `r` | 重新从服务器读取 |
| `q` | 退出 |

名次的排列：已拆除的阶段多的在前；阶段数相同时，爆炸次数少的在前；仍相同时，先完成的在前。

输出接到管道或文件时，计分板是同样的表格，没有颜色：已拆除的阶段在次数之后带 `*`，你自己的一行以 `>` 开头。取出自己的一行：

```bash
./bomb -s | grep '^>'
```

### 终端显示不正常时

程序根据环境变量判断终端的能力，判断与实际不符时画面会错乱。用下面的环境变量指定，对 `./bomb` 与 `./bomb -s` 都有效：

| 现象 | 命令 |
| --- | --- |
| 颜色错乱，或出现闪烁、下划线 | `NO_COLOR=1 ./bomb`，或 `COLORTERM=256color ./bomb` |
| 输入框的边线显示为乱码 | `LC_ALL=C ./bomb` |
| 画面的位置错乱，或窗口中留有上一个画面 | `BOMB_UI=inline ./bomb`：画面依次输出，不占据整个窗口 |
| 只需要文字 | `BOMB_UI=plain ./bomb`：没有画面与颜色。每个阶段一行提示 `phase N of 8> ` 与一行结果 `phase N of 8 defused` |

窗口少于 59 列或 15 行时，程序自动改为依次输出。计分板在窗口少于 74 列时改用窄的表头（`rank bomb def exp`），依次输出时是少于 71 列。没有颜色时，计分板中已拆除的阶段在次数之后带 `*`。

## bomb-light

`bomb-light` 是课堂上演示用的程序。它只有一个阶段，画面与操作同 `bomb`；所有人的 `bomb-light` 相同，
它不连接服务器，爆炸不被记录。先在它上面试用 `objdump` 与 `gdb`：

```bash
chmod +x bomb-light
./bomb-light
objdump -d --disassemble=phase_light bomb-light
```

它的阶段是函数 `phase_light`。

## 完成标准

`answers.txt` 中有 8 行，`./bomb answers.txt` 显示 8 个阶段全部拆除，退出状态为 0
（`./bomb -q answers.txt; echo $?` 输出 `0`）；`./bomb -s` 中以 `>` 标出的一行显示 8 个阶段已拆除。
