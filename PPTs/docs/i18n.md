# Teaching one lecture in two languages

A lecture is written once, in Python, in whatever language its author thinks in.
`--lang en` renders that same lecture in English by laying a **translation
overlay** over it: a `i18n/en.toml` file mapping stable keys to replacement
strings. Nothing about the lecture declares a language, and a lecture with no
`i18n/` directory behaves exactly as it always has.

For the DSL see [dsl.md](dsl.md); for the CLI, [usage.md](usage.md).

## The model

- **Python is the baseline.** `lecture.py` and its modules hold the text as
  written. There is no TOML "source of truth", and nothing is ever written back
  into Python.
- **An overlay is a substitution.** `i18n/<lang>.toml` maps keys to strings;
  `--lang en` loads `i18n/en.toml` and substitutes. No `--lang` means the
  Python, unchanged.
- **It happens once, on the model** — after the lecture is loaded, before any
  renderer runs. Viewer/Marp, PDF/PNG, PPTX, the transcript sheet and the book
  never learn that languages exist; they render a lecture whose text is already
  English.
- **A missing entry falls back to the baseline** and is marked on the slide (a
  faint orange wash, deck only). It is never dropped, never blank.
  `--strict` turns any fallback into a refusal to render.
- **A changed baseline is still used.** Polishing a Chinese line does not revert
  its English translation mid-lecture; `i18n check` is what tells you the two
  have drifted.

The same lecture may carry `en.toml`, `zh.toml`, and `ja.toml` side by side.
The language "name" is only the file name — nothing validates it against a list.

## The workflow

```bash
LEC=path/to/lecture

# 1. Write the skeleton (creates i18n/en.toml; safe to re-run any time).
lecturekit i18n extract "$LEC" --lang en

# 2. Fill in the `text` fields. Untranslated entries are `text = ''`.
$EDITOR "$LEC/i18n/en.toml"

# 3. Rehearse. Anything still untranslated shows through with a faint wash.
lecturekit view "$LEC" --lang en --watch

# 4. Before class: is anything missing or stale?
lecturekit i18n check "$LEC" --lang en
```

Step 1 is re-run whenever the lecture changes: `extract` **merges** rather than
overwrites (see below), so a translator's work survives every run.

`--lang` works on `inspect`, `build`, `render`, `view` and `book`; `--strict` on
the three that render. The default output directory carries the language
(`build/<id>-en-viewer`), so two languages of one lecture do not overwrite each
other. Under `--watch`, `i18n/<lang>.toml` is watched like any other source
file: save it and the deck reloads.

## Keys

A key names one string. Most are derived, so a lecture needs no annotation to be
translatable at all.

| what | key |
| --- | --- |
| lecture title / subtitle | `lecture.title`, `lecture.subtitle` |
| a section's title | `section.<section id>.title` |
| a page's title | `<page id>.title` (book heading: `<page id>.book_title`) |
| a block | `<page id>.<kind>.<n>` — `intro.slide.2` |
| a string inside a block | that block's key plus a name — `intro.image.1.caption` |
| a footnote / a callout bubble | `intro.slide.2.footnote.1`, `intro.image.1.annotation.1` |

`<n>` counts **per kind, in author order on that page**: a page holding a slide,
an aside, then another slide yields `slide.1`, `aside.1`, `slide.2`. The
sub-string names are:

| block | sub-keys |
| --- | --- |
| `slide` `notes` `prose` `aside` | none — the block key *is* the text |
| `highlight`, `bridge` | none, likewise |
| `image`, `side_image` | `caption`, `alt` |
| `row` | `caption`, `item.<n>.caption`, `item.<n>.alt` |
| `architecture` | `caption`, `layer.<n>.title`, `layer.<n>.module.<m>` |
| `table` | `cell.<r>.<c>` — the header row is `r=0` |
| `sidenote` | `title`, `text` |
| `link` | `label` |
| `demo` | `name`, `description` |
| `cover` | `author`, `time` (the cover's title is the page title) |

**Not translated:** `code` content in any language (including `pseudo`),
`p.cite(...)` fields, `p.news(...)` items, image `src`, link URLs, tags and ids.
A translated bibliography is a different bibliography; a translated path is a
broken path.

### Pinning a key

A positional key moves when a page is reordered. `key=` pins one:

```python
p.slide("这一页的核心问题", key="crux")     # -> intro.crux
```

Every block-producing method takes it. A pinned block **does not consume a
number** in its kind's sequence — a page of `slide`, `slide(key="crux")`,
`slide` yields `slide.1`, `crux`, `slide.2` — so pinning one block never
renumbers its neighbours. A key is local to its page (the page id namespaces
it), must not contain `.`, and must be unique within the page; anything else is
a `ValidationError` at build time.

### Animations, bridges, review pages

- An [animation](dsl.md#frames-an-animation) is one slide, so it has **one** set
  of keys, under the id the author wrote: `commit-logging.slide.1`, not
  `commit-logging-2.slide.1`. Translate it once and every frame changes.
- A [bridge](dsl.md#the-tree) keys off its auto id: `bridge-1.bridge.1`.
- A [review page](dsl.md#review-replaying-another-lectures-pages) is looked up in
  the **source** lecture's overlay, under its unprefixed page id — the same rule
  its assets follow. Translate a page once, in the lecture that owns it, and
  every lecture that replays it gets the translation. A source lecture with no
  overlay is not an error; its pages fall back and are marked.

## The file

`i18n/<lang>.toml`, read with the standard library's `tomllib`:

```toml
['intro.title']
src_hash = 'a3f9c1e0'
text = 'What is a process?'
# src: 什么是进程？

['intro.slide.1']
src_hash = '7b21d9aa'
text = '''
An instance of a running program.
 $$ x = 1 $$
'''
# src:
# 一个正在运行的程序实例。
#  $$ x = 1 $$
```

- **`text` is the translation.** `text = ''` means untranslated — grep for it to
  find what is left. Trailing newlines are stripped, so the multi-line form
  above holds exactly two lines.
- **`src_hash`** fingerprints the baseline the entry was translated from (the
  first 8 hex digits of its sha256). Only `extract` writes it and only `check`
  reads it.
- **`# src:`** quotes that baseline, for the translator to read. It is a comment,
  rewritten on every `extract`.

Strings are emitted as TOML *literal* strings wherever possible, so `==mark==`,
`$$ … $$`, a leading space (autobold's escape hatch) and a backslash all survive
the round trip verbatim.

**Slide text is written as slide text.** A `slide` translation goes through the
same two rewrites `p.slide(...)` performs — the `==keyword==` shorthand expands
and flush-left prose lines bold — so a translator writes what they would write
in Python. Both are idempotent, so a translation mirroring the `# src:` comment
(which quotes the baseline *after* the same pass) comes out unchanged. A block
written `p.slide(..., autobold=False)` skips the bolding here too — that is a
choice about the block, not about one of its languages.

## `extract` merges; it never throws work away

| the key is… | what `extract` does |
| --- | --- |
| new | writes it with `text = ''` |
| already translated | keeps the text verbatim |
| translated, baseline since changed | keeps the text, takes the new `src_hash`, adds `# CHANGED: was <old>` |
| no longer in the lecture | moves it to an `# orphaned` section at the end |

Nothing is deleted automatically: an orphan is usually a renamed page, and the
translation is worth keeping until you have looked.

## `check` before class

```
$ lecturekit i18n check path/to/lecture --lang en
missing  queue-burst.slide.2
changed  intro.title
orphaned old-page.slide.1
en: 1 missing, 1 changed, 1 orphaned
```

It exits 1 when anything is missing or changed, 0 otherwise; `--allow-changed`
narrows that to missing only, for the common case of a wording polish you have
decided not to re-translate yet.

## lecturekit's own strings

The framework prints a few strings of its own — the deck's 参考文献 page, the
viewer's ≡ 大纲 button, the book's 延伸阅读 / 动手试试 / TODO headings, the 图
prefix a `[@ref]` renders as. These are not part of an overlay: they belong to
lecturekit, not to a lecture. They come from one table (`i18n.UI_STRINGS`),
keyed on the applied language, and an unknown language falls back to the Chinese
set rather than blocking the render. Adding a language to that table is a
one-line change.

## The book

A book is an *ordering*, so the only text it owns is its front matter:

```bash
lecturekit i18n extract path/to/book --lang en    # -> book/i18n/en.toml
lecturekit book path/to/book --lang en            # -> build/book-en/
```

`book/i18n/en.toml` holds three keys — `book.title`, `book.subtitle`,
`book.preface`. Every chapter translates itself through **its own lecture's**
overlay, so a lecture is translated once and both the deck and the book use it.

## What this deliberately is not

- **No in-viewer language toggle.** A deck is rendered in a language; a switch
  would mean shipping two decks and keeping their slide numbers in step.
- **No TOML baseline.** Python strings do not become placeholders; the source
  stays readable prose.
- **Nothing is written back into Python.** `extract` only ever writes `i18n/`.
- **A changed baseline never invalidates a translation.** The gettext model
  (stale entry → drop it) would blank slides mid-lecture on the day the author
  polished a sentence.
