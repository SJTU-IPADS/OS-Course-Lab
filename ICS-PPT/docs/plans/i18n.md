# Plan: per-lecture language overlays (`--lang`)

Status: **implemented** on 2026-08-23; see [../i18n.md](../i18n.md) for the
shipped behaviour, which this plan describes. Kept as the record of what was
decided and why. Implement
entirely inside the `lecturekit` repo (this submodule); the course repo only
gains a short CLAUDE.md paragraph at the end. **Existing lectures must not
change** — every lecture without an `i18n/` directory behaves exactly as today.

## 1. The model (what was decided, and why)

- Python (`lecture.py` + its modules) is the **baseline** text, in whichever
  language the author wrote it. Nothing declares that language.
- `<lecture>/i18n/<lang>.toml` is an **overlay**: a map from stable block keys
  to replacement strings. `--lang en` loads `i18n/en.toml` and substitutes
  into the AST; no `--lang` means pure Python. The same lecture may have
  `en.toml` and `zh.toml`; the language name is only the file name.
- Substitution happens **once, on the model** — after `load_lecture`, before
  any renderer. Viewer/Marp, PDF/PNG, PPTX, transcript and book never learn
  that languages exist.
- Keys are derived automatically (`<page id>.<kind>.<n>`); an author can pin
  one with `key="…"`. Every overlay entry stores a hash of the baseline text
  it was translated from. When the baseline changes the entry is **still
  used**, and `i18n check` reports it as changed — never silently dropped
  (the author polishes wording daily; gettext-style invalidation was rejected).
- A missing entry falls back to the baseline text and is **visibly marked on
  the slide** (faint red wash, deck only; the book prints nothing). `--strict`
  turns that into an error.
- Not in scope (explicitly rejected): in-viewer language toggle; a TOML
  baseline (“Python strings become placeholders”); writing TOML back into
  Python; editor jump-links from the viewer.

## 2. Translation domain

Text that is overlaid (every user-visible string that is prose):

| where | content path |
| --- | --- |
| `Lecture.title`, `Lecture.subtitle` | lecture-level keys `lecture.title`, `lecture.subtitle` |
| `Section.title` | `section.<section id>.title` |
| `Page.title`, `Page.book_title` | `<page>.title`, `<page>.book_title` |
| `slide`, `prose`, `aside`, `notes`, `handout` | `content["content"]` (check the exact dict shapes in `dsl.py`) |
| `highlight` | `content["text"]` |
| `sidenote` | `title`, `text` |
| `link` | `label` |
| `image` / `frames` / `row` / `architecture` | `caption` (+ `alt`); row items' captions; architecture layer titles and module labels |
| `table` | `headers[i]`, `rows[i][j]` |
| `bridge` | its lines |
| `cover` | title / author / time (not logos) |
| `demo` | name / description text |
| `Block.footnotes[i]` | `<key>.footnote.<i>` |
| `Block.annotations[i].text` | `<key>.annotation.<i>` |
| `Book.title`, `Book.subtitle`, `Book.preface` | `book/i18n/<lang>.toml`, keys `book.title` etc. |
| lecturekit's own fixed strings | see §6 |

Not overlaid: `code` content (any language, incl. `pseudo`), `p.cite(...)`
fields, `p.news(...)`, image `src`, `link` url, tags, ids.

## 3. Keys

Auto key for a block: `<page id>.<kind>.<n>` where `n` is the 1-based index
**among blocks of the same kind on that page**, counting in author order over
the *pre-expansion* page (so a `frames` page yields one set of keys, shared by
every frame — use `FrameGroup.id`, not the `-1/-2` frame ids). Title:
`<page id>.title`. Sub-strings hang off the block key:
`intro.slide.2.footnote.1`, `intro.image.1.caption`, `intro.table.1.cell.r.c`
(header row is `r=0`), `intro.architecture.1.layer.2.module.3`.

Explicit key: `p.slide("…", key="why")` → `intro.why` (and its sub-strings
`intro.why.footnote.1`). Add `key: str | None = None` to `model.Block`; the
`PageBuilder` methods accept it as a keyword; `check_block` rejects a key that
is empty, contains `.`, or repeats within a page. A pinned block does **not**
consume a number in the auto sequence of its kind — `slide.1`, `why`,
`slide.2` — so pinning one block does not renumber its neighbours.

Review pages (`review_section`): their ids are `<src lecture id>/<page id>`.
Look them up in the **source** lecture's `i18n/<lang>.toml` (directory from
`Lecture.borrowed`), with the unprefixed page id. This mirrors how assets
follow the source.

Bridge pages: they have auto ids `bridge-1` …; key `bridge-1.bridge.1`.
Cover: `cover.cover.1.title` etc.

## 4. File format

`i18n/<lang>.toml`, read with the stdlib `tomllib`. Written by `extract` with
a small in-house emitter (~40 lines: quoted keys, `'''` literal multi-line
strings so `==mark==`, `$$`, leading spaces and backslashes survive verbatim;
a string containing `'''` falls back to a basic `"""` string with escapes).

```toml
# i18n/en.toml — generated skeleton; edit the `text` fields.
# Lines starting with `#` are comments; `src` is the baseline text this entry
# was translated from, kept for reference.

["intro.title"]
src_hash = "a3f9c1e0"
text = "What is a process?"
# src: 什么是进程？

["intro.slide.1"]
src_hash = "7b21d9aa"
text = '''
An instance of a running program.
 $$ x = 1 $$
'''
# src:
# 一个正在运行的程序实例。
#  $$ x = 1 $$
```

Rules:

- Leading newline after `'''` is TOML-stripped; trailing newline is not — the
  loader `rstrip("\n")`s `text` once, and compares against the baseline the
  same way (`dsl` already strips code fences; don't double-normalize).
- `src_hash` = first 8 hex of sha256 of the baseline string (after the same
  rstrip). It is written by `extract` and only read by `check`/the loader.
- An empty `text = ""` means **untranslated** (treated as missing: fallback +
  marker). `extract` emits empty text for new entries so the translator can
  grep for `text = ""`.
- The `# src:` comment is convenience only and is rewritten on every
  `extract`. Keep it after the entry so the key/hash/text stay greppable.

## 5. Code changes, by file

All under `lecturekit/lecturekit/`. Suggested new module: `i18n.py`.

### `model.py`
- `Block.key: str | None = None`.
- `Lecture.lang: str | None = None` (the overlay actually applied; renderers
  use it only to pick fixed strings in §6) and
  `Lecture.untranslated: tuple[str, ...] = ()` (keys that fell back — the
  viewer marks these, `--strict` errors on them).
- Validation: `check_block` enforces key rules above.

### `dsl.py`
- Every block-producing `PageBuilder` method gains `key=` and threads it into
  `model.Block`. Page-level `p.title` has no key (it's `<page>.title`).
- No other change: auto keys are computed in `i18n.py` from the built model.

### `i18n.py` (new)
- `walk(lecture) -> Iterator[Entry]`: yields `(key, getter, setter)` for every
  string in the domain of §2, in deterministic order. This single walker is
  shared by `extract`, `check`, and `apply`. Keep the key rules in one
  function (`block_key(page, block, counters)`) so the three commands cannot
  disagree. Frames: walk the *first* frame of a group and apply its results
  to all frames (blocks are structurally identical; the figure block differs
  only in `src`).
- `load_overlay(dir, lang) -> dict[key, (src_hash, text)]`; raises a clear
  error naming the file and TOML line on parse failure. Missing file with an
  explicit `--lang` is an error (a typo should not silently render the
  baseline).
- `apply(lecture, overlay, *, strict) -> Lecture`: rebuild the (frozen)
  dataclasses with `dataclasses.replace`, collecting untranslated keys. Under
  `strict` raise `ValidationError` listing them. Also resolves borrowed
  pages by loading each `Borrowed.directory`'s overlay lazily.
- `extract(lecture, existing_overlay) -> str` (TOML text) merging rule:
  existing `text` kept; new keys get `text = ""`; keys whose hash differs
  keep their text, get the new `src_hash`, and a `# CHANGED: was <old hash>`
  comment; keys no longer in the lecture are emitted at the end under a
  `# orphaned` banner (never deleted automatically).
- `check(lecture, overlay) -> Report` with lists `missing`, `changed`,
  `orphaned`; formatter prints one line per key.
- Hash helper shared by all of the above.

### `cli.py`
- `--lang LANG` on `inspect`, `build`, `render`, `view`, `book`, plus
  `--strict` on `render`/`view`/`book`. Apply the overlay right after
  `load_lecture` (one helper `load_lecture_for(args)` used by every command).
- Default output dir becomes `build/<id>-<lang>-viewer` / `-pptx` when
  `--lang` is set, so two languages don't clobber each other. Explicit `--out`
  wins as today.
- New subcommand group `i18n` with `extract <lecture_dir> --lang X` (writes
  `i18n/X.toml`, creating the directory; prints counts new/changed/orphaned)
  and `check <lecture_dir> --lang X` (exit 1 if missing or changed is
  non-empty; `--allow-changed` to only fail on missing).
- `book`: also apply `book/i18n/<lang>.toml` to `BookModel` title/subtitle/
  preface; each chapter uses its own lecture's overlay. `i18n extract` on a
  book dir (a dir with `book.py`) emits the book-level file.

### `dev_server.py`
- `_watch_paths`: when a lang is active, watch `i18n/` of the lecture and of
  every borrowed source; a TOML edit re-renders like a source edit.
- Pass `lang`/`strict` through the re-render callback.

### `renderers/viewer/`
- Marp deck: a block whose key is in `Lecture.untranslated` gets a wrapper
  `<div class="lk-untranslated">` (theme CSS: faint `#F15A24` wash at ~12%
  alpha, no border) so a missing translation is visible on the projector
  during rehearsal. Only the viewer does this; PPTX/book/transcript ignore.
- The outline shell: the "≡ 大纲" button and other chrome strings come from
  the fixed-string table (§6); emit them into `lecture.json` as `ui: {...}`
  so `viewer.js` reads them instead of hardcoding.

### `renderers/latex/`, `references.py`, `book.py`
- Replace hardcoded headings (参考文献, 延伸阅读, 动手试试, TODO box text,
  figure prefix "图") with lookups from §6 keyed on `lecture.lang`.
- `BookModel` gets `lang` too so the preamble picks `ctex` vs plain fonts
  sensibly (keep `ctex` always loaded — English books still contain CJK in
  review/figures; just choose `\chapter` names from the table).

### `serialize.py`
- Emit `key`, and `lang` / `untranslated` at the lecture level, so `build`
  output and the viewer can see them.

## 6. lecturekit's own fixed strings

One table in `i18n.py`:

```python
UI_STRINGS = {
    "zh": {"references": "参考文献", "outline": "大纲", "further_reading": "延伸阅读",
           "demo": "动手试试", "todo": "TODO", "figure": "图", "page": "P"},
    "en": {"references": "References", "outline": "Outline", "further_reading": "Further reading",
           "demo": "Try it", "todo": "TODO", "figure": "Figure", "page": "P"},
}
```

Lookup: `lecture.lang` if present in the table, else `"zh"` (the current
behaviour). An unknown lang (say `ja`) overlays the lecture text but falls back
to `zh` chrome with a one-line warning — don't block on chrome.

## 7. Docs and tests

- `docs/i18n.md` (new): the model, the key rules, the TOML format, the

  from `dsl.md` (`key=`), `usage.md` (`--lang`, `--strict`, output dir), and
  `book.md` (book-level overlay).
- Tests (`tests/test_i18n.py`): key derivation incl. frames / pinned keys /
  table cells / borrowed pages; overlay apply with fallback + `untranslated`
  list; strict error; extract merge (new / changed / orphaned) round-trips
  through `tomllib`; TOML emitter preserves leading-space lines, `==mark==`,
  backslashes, and a string containing `'''`; CLI `--lang` default out dir;
  UI string fallback. Run with `python3 -m pytest`.
- Course repo: one paragraph in `CLAUDE.md` under “Running the CLI” showing
  `scripts/view.sh <lec> --lang en` and the extract/check commands, and a line
  in `soul/writing.md`-adjacent guidance is **not** needed (no authoring
  preference changes).

## 8. Suggested order of work

1. `model.Block.key` + `dsl` plumbing + validation + tests (small, isolated).
2. `i18n.walk` / `block_key` with tests — this is the contract everything
   else depends on; get frames, tables, borrowed pages right here.
3. TOML emitter + `extract`, then `load_overlay` + `apply` + `check`.
4. CLI flags, output-dir naming, `i18n` subcommands.
5. Fixed-string table and its call sites (viewer, references, latex).
6. Viewer untranslated wash + `--strict`.
7. Dev-server watch paths.
8. Book-level overlay.
9. Docs. Then smoke-test on a real lecture: `i18n extract
   ../before-or-after-atomicity --lang en`, translate three pages by hand,
   `view --lang en`, confirm fallback marks and `check` output.

## 9. Open details the implementer may settle alone

- Whether `notes` belongs in the domain (lean yes — presenter notes in the
  wrong language are useless; cheap to include).
- Marker style for untranslated blocks (any faint wash that is obviously not
  part of the design).
