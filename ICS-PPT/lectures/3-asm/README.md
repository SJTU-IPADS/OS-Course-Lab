### 第二部分：循环控制与跳转指令（第 44 ~ 61 页）

> **核心任务**：单次乘加已经实现，向量维度是 4096。CPU 如何让同一段指令执行 4096 次并在该停的时候停下？本部分按问题推进：顺序执行做不到循环 → `dot_product` 的汇编如何跳转 → 条件跳转从哪里得到条件（标志位、`cmp`/`test`）→ 条件跳转指令一览 → 直接跳转之外为什么还要间接跳转（`switch` 与跳转表）→ 拓展 `cmov`/`setX`。2026-10-07 重组，标题由「循环控制与状态机推进」改为「循环控制与跳转指令」。

* **向量内积和控制流（两页）**：第一页：核心循环的 C 代码；顺序执行的规则（`%rip` 存放下一条要取出的指令的地址，执行后加上指令长度，由 CPU 完成），配图 `pc-increment.svg`（`-Og` 循环体 7 条指令的地址与长度）。不出现「虚拟地址」。第二页：页面最上方是一个代码块（2026-10-08 新增），左边是单次乘加的 C 代码 `sum += w[0] * x[0];`，右边是第一部分得到的三条指令 `movl (%rsi), %eax`、`imull (%rdi), %eax`、`addl %edx, %eax`；只有顺序执行时，4096 次乘加要把同样的指令写 4096 份（配图 `loop-unroll.svg`，2026-10-07 去掉了原图的回环箭头），代码长度随 n 增长且 n 在运行时才确定；需要改写 `%rip` 的指令，即跳转指令。

## 配图在页面上的位置

* **侧图放在页边距以内**：`p.side_image(..., alt="contain")` 的图，外侧与标题的一端对齐（距页面边缘 80 px），内侧距正文 40 px，下端距页面底边 40 px。这是主题的规则（`themes/basic-office.css`，说明见 `docs/dsl.md` 的 `p.side_image` 一节），页面源码只写 `width`。`width` 是图与外侧页边距合计占页面宽度的比例，图自身最宽为 `width` 减 40 px；正文一栏的宽度只由 `width` 决定。
* **各侧图的宽度**：`loop-jumps` 40%，`address-space` 30%，`call-ret` 42%，`stack-args` 42%，`bias-stack` 44%，`main-stack` 42%，`frame-layout` 37%，`xyb.png` 40%，`mat-stack` 38%，`tensor-stack` 38%。同一张图出现在连续两页时，两页的宽度相同。
* **竖排的栈图一行 8 字节**：同一张图中 8 字节的行高度相同；4 字节的数据一行放两格，行内左侧是高地址，地址从左到右、从上到下降低，格内写出它的地址（`main-stack.svg`）。大小没有确定数值的区域（调用者的其他数据）画得比一行高。
* **侧图的画布贴合图的内容**：四周各留 10 ~ 25 px。画布一侧的留白较多时，图在页面上偏向另一侧，并且整体缩小。
* **整页宽的图按画布居中**：`figure(p, name, 1120)` 的图，内容要位于画布正中。内容偏向一侧时，在图源的 `save(...)` 中用 `left=` 平移画布（见 `diagrams/svgkit.py` 中 `svg` 的说明），图中的坐标保持原样。`array-address.svg` 的一行方格两端对称，以方格为准，伸出的 `w_base` 标注不计。
* **核对留白**：`python3 diagrams/margins.py` 打印每张图左、右、上、下的留白，单位是画布像素（需要 `rsvg-convert` 与 Pillow）。整页宽的图左右留白相差 8 px 以上时需要调整。`diagrams/render.sh` 结尾的 `check_bounds.py` 检查标注是否越出画布，画布用 `left=` 平移后按平移后的范围检查。
