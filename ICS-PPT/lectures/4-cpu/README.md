# ICS 第四讲 · 指令如何在 CPU 中重叠执行

本讲从一段连续的 x86-64 汇编指令与 PC 顺序执行模型开始，讨论处理器如何让多条指令重叠执行、重叠能快多少，以及指令之间为何需要等待。

中文是基线（写在 Python 里）。五个阶段采用 MIPS 的五级经典模型，它是教学模型；例子是第 3 讲 `gcc -Og -fcf-protection=none` 编译出的 x86-64 循环体，不另设一套指令集。

## 这一讲不讲

Y86 指令编码、HCL、顺序实现的数据通路、五级转发电路、判断何时 stall 与插入 bubble 的控制逻辑、流水线异常、architecture lab。乱序执行只讲两条规则（操作数就绪即执行、按程序顺序写回），不讲寄存器重命名、重排序缓冲区与保留站；多发射只讲硬件复制 n 份、每个周期开始执行 n 条，不讲取指带宽与发射队列。超线程只讲复制 PC 与寄存器堆、其余硬件共用、取指轮流、执行部件挑就绪的指令不分线程、各线程按程序顺序写回本线程的寄存器堆；不讲各线程占用等待区的份额、细粒度多线程与操作系统的调度。转发只指出结果（执行阶段算出的、或访存阶段读出的）直接送进下一条的执行阶段，不画电路；分支只指出已经取进来的指令在猜错时作废，不给一个固定的作废条数（图上画的是五级模型，判定时已取进来两条）。

## 术语

与第 3 讲一致：
- 正文计数用「周期」；「拍」只在「停一拍」和讲稿口语里；「时钟」只指时钟信号或周期长短。
- 「阶段」说一条指令经过的五步，「级」说流水线的硬件分级（五级、级间寄存器、最慢的一级），不用「段」。
- stall、bubble 用英文，在 `stall-bubble` 页正文定义（stall：级间寄存器在时钟沿保持原内容；bubble：级间寄存器在时钟沿装入一条空指令），之后的正文写「stall 一个周期」「插入 bubble」，不写「气泡」。名词「停顿」与「停一拍」只在讲稿口语；图格子「停」表示指令在这个周期 stall，留在原级。
- 第四部分沿用上面几条：时空图的一行是一块 GPU，一列是一个周期（一块 H200 处理 21 层的时间）；GPU 在这个周期没有请求可算的格子是 bubble，图上画成白底灰色虚线框，写「bubble」，与 `stall-bubble` 页的 bubble 同样画法，正文写「bubble」「插入 bubble」。讲师稿里的「气泡」「停」「拍」2026-10-27 按这一条改过，讲师补交的图 2026-10-28 也按这一条改过。
- 一律「作废」。
- 「转发」在 `forward-fig` 页正文定义；「开始执行」沿用第 3 讲，动词「发射」与「发射宽度」只在讲稿里，技术名「超标量」是 `superscalar` 页的标题。
- 乱序执行五页（`ooo-inorder` 至 `ooo-compare`）的红色「停」格表示译码后的指令在处理器内部等待执行（等操作数，或按程序顺序等前面的指令，或等执行部件），与第二部分「留在原级」的「停」格不同；虚线格「等待写回」表示结果已算出、等它前面的指令写回。「顺序执行」指第一部分的单周期实现，与乱序执行对照的是「顺序流水线」。
- 「超线程」在 `smt-hw` 页正文定义，「同时多线程（SMT）」与「逻辑处理器」只在讲稿里；「线程」「核心」「多核」沿用第 3 讲「线程并行：CPU 多核与 GPU」一页。超线程五页的图中线程 A 一律蓝色、线程 B 一律橙色（第四部分请求 1、请求 2 的配色），这几页的图不用五阶段配色。
- 「标志位」不写「条件码」；正文不裸用 load / store。
- data hazard、control hazard 用英文，不译成「数据冒险」「控制冒险」；统称 hazard 与 load-use data hazard 只在讲稿里，正文写「读内存后马上使用」。

## 第四部分的模型与数值依据

- [NVIDIA H200 官方规格](https://www.nvidia.com/en-us/data-center/h200/)：每块 141 GB HBM3e，显存带宽 4.8 TB/s。
- [Meta 的 Llama 3 论文](https://arxiv.org/html/2407.21783v3)，第 3.2 节与表 3：Llama 3.1 405B 为稠密 Transformer，126 层，隐藏维度 16384。按约 4050 亿参数、每参数 2 字节估算权重约 810 GB，ceil(810/141)=6 只是权重容量下限。
- [Meta 参考实现](https://github.com/meta-llama/llama3/blob/main/llama/model.py) 的前向过程逐层执行全部 Transformer 层，输入词嵌入按词号查行。正文用「经过全部层、使用各层稠密权重」；讲稿将约 810 GB 的主要权重扫描估算与缓存、矩阵分块决定的实际显存流量区分。KV 缓存复用历史 K、V，不跳过新词的各层权重计算。

六卡示例假定各级用时相同，忽略通信与 KV 缓存等额外空间；不是实际部署卡数、利用率或测速的保证。单请求访问各级权重的过程是串行的，不能直接用六卡带宽之和计算其延迟。

流水线并行的定义参考 [PyTorch Pipeline Parallelism](https://docs.pytorch.org/docs/main/distributed/pipelining.html) 与 [vLLM Parallelism and Scaling](https://docs.vllm.ai/en/stable/serving/parallelism_scaling/)：模型执行划分为若干阶段，不同请求或小批次在不同阶段重叠执行。
