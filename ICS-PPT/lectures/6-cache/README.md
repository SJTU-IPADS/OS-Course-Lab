# ICS · 局部性与缓存

独立的一讲：从 `dot_product` 对内存的需求出发，说明内存的构成与它同处理器的速度差距，用局部性与层次结构回答这个差距怎样被缩小，再讲缓存模型及其访问、写策略与性能指标，把这些用到程序的编写上，最后以大模型推理中的 KV Cache 为例说明软件缓存的容量、访存与分配。素材来自 `lectures/ICS2/2-5-ram`（存储技术）、`2-6-locality`（局部性）与 `2-7-cache`（缓存）。前置知识是第一至第五讲（数据表示、汇编、CPU、GPU）。虚拟内存尚未讲授，本讲不出现虚拟地址、地址翻译、页表与 TLB。

中文是基线（写在 Python 里），英文是 `i18n/en.toml` 翻译覆盖层。

## 结构

封面、目录页之后分六个部分，每部分以一页 `lecture.bridge(...)` 开头，只写「第 x 部分：标题」；该部分的起点问题写在 `pages.py` 中该部分开头的注释里；除第四部分外，每部分以练习结束（题目一页，答案一页或几页，需要逐次说明的答案是动画，题面重复在答案之上），扩展内容是标题为 `sidebar：…` 的页。共 224 张幻灯片，其中 34 页是动画（`p.frames`），每帧一张。

贯穿全讲的程序是 `dot_product(const int *w, const int *x, int n)` 与按行存放的矩阵 `W[M][N]`：第一部分提出它对内存的需求，第二部分用局部性解释它的运行时间，第三部分说明缓存怎样判断命中（冲突不命中也用 `dot_product` 的两个数组演示），第四部分度量缓存，第五部分改写程序。第六部分自成一线，从大模型逐个生成 token 时的重复计算出发，不使用 `dot_product`。

## 课堂演示

演示程序都在 `examples/` 下，按 `p.demo` 的命令编译运行（`gcc` 与 Linux 的 `sysfs`）。页面上的输出录于同一台机器，所以各页的数字互相对应：`latency.c` 测得的各级延迟（没有单独的演示页）用于多级缓存与性能指标两页，`mountain.c` 的输出（没有单独的演示页）存为 `diagrams/mountain.txt`，用于存储器山的图，`cacheinfo.sh` 的容量用于存储器山的各层边界。每个演示页提出一个问题，或验证上一页的一个预测；页面文字说明程序测量什么、读哪几行（加粗的行）、得出什么结论。页面不命名运行它的机器。

| 页 | 程序 | 内容 |
| --- | --- | --- |
| 矩阵按行与按列求和（37） | `rowcol.c` | 4096 × 4096 的 int 矩阵按行与按列求和，每个元素的时间 |
| 缓存的参数（66） | `cacheinfo.sh` | 从 `/sys/devices/system/cpu/cpu0/cache/` 读出各级缓存的容量、路数、行长与组数；页面下方的示意图（`diagrams/cache_params.py`）说明三个参数与容量的关系 |
| 缓存块的长度（118） | `linesize.c` | 两次相依读取的地址间隔变化，耗时在 56 与 64 字节之间翻倍 |
| 六种循环顺序的运行时间（185） | `matmul_order.c` | 六种循环顺序每次内层迭代的时间，三类的次序与不命中次数一致 |
| 无缓存与有缓存的运行时间（207） | `kv_decode.c` | 单头注意力生成 1024 个 token，统计 k、v 的投影次数与运行时间，并逐位比较两种输出 |

`examples/.gitignore` 忽略编译产物。

实测结果中有一点没有查明原因，页面只陈述数据：存储器山步长 16 的一列整体偏低。

## 图

图的源文件在 `diagrams/`，运行 `sh diagrams/render.sh` 生成 `assets/*.svg`，`assets/*.svg` 不手改。公共部件：`svgkit.py`（绘图与配色）、`cachekit.py`（缓存的组、行、块的版式）、`cdraw.py`（CPU 与内存的示意图）、`kv_kit.py`（第六部分的格子与图例，配色：缓存中已有为浅蓝，新写入为橙，复用为绿，重复或浪费为红）。`storage_levels.py` 画硬件层次，`software_layers.py` 用同一版式画软件的操作范围、资源缓存与文件缓存三张图：硬件按访问速度自上而下竖排，应用与操作系统在左侧，图放在文字或代码旁边。`check_bounds.py` 与 `margins.py` 检查图是否越界。

配色在全讲统一：标记为紫，组索引为蓝，块偏移为橙，内存与 DRAM 为绿，当前被请求的数据为橙，命中为绿，不命中为红；缓存中的行用浅蓝填充。存储器山的热力图与两条切片的数字读自 `diagrams/mountain.txt`，页面文字中的对应数字由 `pages.py` 从同一文件解析，两处不会不一致。第四部分的条形图由脚本按数字计算长度，按比例绘制。外部图片有资源缓存一页的两个游戏图标（`diagrams/icons/`，取自 App Store，版权归腾讯与米哈游，页脚注明）与文件缓存一页的 C 语言图标（`diagrams/icons/c-language.png`，取自 Wikimedia Commons 的 `C Programming Language.svg`，公有领域，该页面注明它可能受商标保护，页脚注明），`software_layers.py` 把它们以 base64 嵌入 SVG。

## 动画

逐步发生的过程用 `p.frames` 展开成帧，每帧只比上一帧多一步：内存读写（最简单的内存模型、DRAM 的行列选择、内存模块、DRAM 内存模型下的访存模式、读事务与写事务）、步长为 1 与步长为 k 的访问、不命中的三种类型、CPU 与缓存之间的数据流、直接映射与组相联的访问与替换、全相联的标记比较、写入的一致性问题、写命中与写不命中的两种策略（一个动画一种策略，不并排）、多级缓存的逐级查找、矩阵乘法三类循环顺序的内层迭代（只画第 1、2、8 次迭代）、无缓存与有缓存时的 k、v 投影（第六部分）、按块分配的块表、第三部分练习的访问序列（`org_exercise.py`）。每个动画是 `diagrams/` 下的脚本生成的一组 `assets/<名>-N.svg`，命中、不命中、LRU 状态与不命中次数都由脚本中的模拟算出，页面文字中的数字与图一致。帧前的文字每帧都显示，帧后的文字只在最后一帧出现。

## 约定

- 术语：缓存、命中、不命中、块、行、组、有效位、标记、组索引、块偏移、冷不命中、冲突不命中、容量不命中、写直达、写回、写分配、非写分配。
- 用词：memory 与 main memory 都写「内存」，cache 写「缓存」，与其他各讲一致。「存储器」只用于把缓存、SSD 与磁盘包括在内的定名：存储器层次结构、存储器山，以及随机访问存储器（RAM）。
- 记号：地址 $m$ 位，$S = 2^s$ 个组，每组 $E$ 行，块 $B = 2^b$ 字节，标记 $t = m - s - b$ 位，容量 $C = S \times E \times B$（只计数据）；地址从高位到低位依次是标记、组索引、块偏移。
- 不引用其他讲；术语在第一次出现处用一句话说明；页面不命名运行演示的机器，涉及硬件的示例取当前产品的参数。
- 练习答案由程序模拟得出，算法写在答案页的讲稿中。
- 代码页中的注释是英文，不翻译。
- 英文版只同步译文，不核对排版。
