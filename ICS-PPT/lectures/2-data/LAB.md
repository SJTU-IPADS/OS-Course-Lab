# ICS 第二讲 · 实验设计：`gguf-lens`

本讲的实验只有一个目标：**读懂一个真实的模型权重文件，并说明它为什么是这个大小**。
文件是第一讲留下的那个对象，本讲的每一个知识点在实验里都有一次落地。

设计依据是 [refs/advice/ICS课程现况和改革建议.md](../../refs/advice/ICS课程现况和改革建议.md) 的三条：
实验按 **观察型 / 构造型 / 诊断修复型 / 优化型 / 对抗取证型** 分类；允许学生使用 AI，
但把评价锚点从产物移回人；以及用一个贯穿全课程的 nano-ollama 项目串起各讲。

---

## 一、实验对象

三档同一格式的文件，覆盖调试与验收两种用途：

| 文件 | 大小 | 用途 |
| --- | --- | --- |
| `tiny.gguf` | 224 B | 调试。整个文件可以一次打印出来，逐字节核对。生成脚本见 `examples/make_gguf.py` |
| `small.gguf` | 数 MB | 验收。Q4_0 量化，含数十个张量与完整的元数据 |
| 学生自取的模型 | 1.9 GB | 规模验证。`ollama pull llama3.2` 得到，检验 64 位字段与文件偏移是否处理正确 |

小文件用于定位错误，大文件用于暴露 32 位溢出。两者格式完全相同，工具只写一份。

## 二、三个部分

### A 观察：`gguf-lens`

写一个命令行工具，读出文件头、元数据键值对与张量清单，不使用任何第三方 GGUF 库，
只用 `fread` 与显式宽度类型。三个子命令，每条记录一行，字段用制表符分隔，
输出可以直接交给 `awk` 或 `sort` 处理：

```
$ ./gguf-lens header small.gguf
magic     GGUF
version   3
tensors   291
kv        24

$ ./gguf-lens tensors small.gguf | head -2
token_embd.weight     Q4_0    2   128256  4096   283115520
blk.0.attn_q.weight   Q4_0    2     4096  4096     9437184

$ ./gguf-lens account small.gguf
header+kv        18944
tensor info      41352
padding            216
tensor data  1985003520
total        1985063936
```

硬性验收条件：`account` 的 `total` 与 `ls -l` 给出的字节数**完全相等**。
对齐填充是可以算出来的，因此这里不接受近似。任何一个字段的宽度或字节序读错，
账目就对不上，学生必须自己找到差在哪一个字段。

评分要点：`total` 精确相等；字节序的合成过程写成显式代码而非 `memcpy` 到 `uint32_t`；
每个张量的类型与元素数正确，且尺寸由类型的位宽算出而非硬编码。

### B 构造：`q4`

实现 Q4_0 的量化、反量化与 4 位打包：

```c
void     quantize(const float *x, block_q4_0 *out);   /* 32 个权重 -> 18 字节 */
void     dequantize(const block_q4_0 *in, float *x);
uint8_t  pack(int lo, int hi);
uint8_t  add_packed(uint8_t a, uint8_t b);            /* 两个通道各自独立溢出 */
```

四项自动测试，全部可判定：

1. **误差上界**。对任意输入，每个权重的绝对误差不超过存回后的缩放系数，
   即 `|w - dequant(quant(w))| <= |d|`，其中 `d` 是从 `out->d` 反读出来的 fp16 值；
   且未落在编码 15 上的权重满足更紧的 `<= |d|/2`。两条都要测。
   写出这两个界的差别来自哪里，是这一项的评分点：编码表示 −8 到 7，
   与组内极值反号且幅度相近的权重被截到 `7d`，误差因此可达一个完整步长。
2. **穷举等价**。`add_packed` 在全部 65536 对输入上与逐通道参考实现一致，
   错误计数必须为 0。讲义中给出的实现在同一测试下 `a + b` 错 30720 对。
3. **幂等**。`quantize` → `dequantize` → `quantize` 之后码字不变。
4. **逐字节比对**。对助教给定的一组 32 个权重，产出的 18 字节与参考块完全相同。
   这一条同时锁住两个容易写反的细节：缩放系数取 `extreme(x) / -8` 而不是 `absmax / 7`
   （后者浪费掉 16 个编码中的一个），以及 `qs[j]` 的两个半字节配的是第 `j` 与第
   `j+16` 个权重。两者都能通过前三项测试，只有逐字节比对能判定。

第 4 条把这一部分变成 bit-exact 的实验，「结果差不多」不构成通过。

### C 诊断修复：`five-bugs`

给出五个能编译、能运行、输出看起来合理但结果错误的实现。错误一律不表现为崩溃，
学生只能从数值回溯到字节。每个缺陷要提交四项：

- **第一处分歧**：哪个字段、哪个字节偏移、或哪一轮循环；
- **证据链**：用 A 部分自己写的工具或 `xxd` 打印出来的那几行；
- **修复用的 prompt**：包含现象、定位与约束三部分，要求 AI 只改这一处；
- **最终 diff**。

五个缺陷全部出自本讲：

| 编号 | 表现 | 第一处分歧 | 讲义页 |
| --- | --- | --- | --- |
| b1 | `version` 读成 50331648 | 按大端合成 `uint32` | `endianness`、`read-the-field` |
| b2 | 大张量的元素数为负，账目差数 GB | 用 `int` 存 `uint64` 的元素数，2048×2048×512 越界 | `numeric-range`、`casting` |
| b3 | 含 0x80 以上字节的张量名乱码 | `char` 有符号，逐字节读入时发生符号扩展 | `expand-truncate` |
| b4 | 个别权重反量化后偏离一个大数 | 打包加法直接写 `a + b`，低通道的进位进入高通道 | `nibble-add` |
| b5 | 反量化后每个权重都能对上，整块的顺序却是错的 | `qs[j]` 的两个半字节配成第 `j` 与第 `j+1` 个权重，而真实的配对是第 `j` 与第 `j+16` 个 | `q4-block`、`nibble-packing` |

b1 与 b3 在 `tiny.gguf` 上就能定位，b2 只在完整的模型文件上出现，
b4 与 b5 需要写测试才能观察到：b5 尤其只在逐字节比对下暴露，
逐个权重看误差一切正常。三种定位方式各有一次。

## 三、考核

产物给出分数，面谈给出门槛。这两者分开。

**产物（100 分）**，其中标记为核心系统操作的项合计 60 分：

| 项 | 分 | 核心 |
| --- | --- | --- |
| A `header` / `tensors` 正确 | 15 | |
| A `account` 与 `ls -l` 精确相等 | 20 | ● |
| B 四项测试全过 | 25 | ● |
| B 代码只用位运算与显式宽度类型 | 10 | |
| C 五处定位与证据链 | 15 | ● |
| C 五个 prompt 与 diff | 15 | |

**面谈（随机抽查 12%）**，每人 5 分钟，两件事：

1. 当面读一段 32 字节的 hexdump，说出 `version` 与第一个张量的类型；
2. 从该生 `LAB.md` 里挑一条追问，例如「你的账目里 216 字节的填充是怎么算出来的」。

抽中且无法解释的，核心系统操作 60 分归零，并进入后两个实验的必抽名单；
能解释的，不影响任何分项。抽签用全班可验证的公开种子。

**AI 的使用**是允许的，并且要求记录。`LAB.md` 里写明哪些部分由 AI 生成、
改了它哪里、为什么改。C 部分的提交物本身就是 prompt，这一部分把与 AI 的协作
变成被考核的内容。

**提交物**：源码、可重跑的测试、以及一份 `LAB.md`。不接受截图作为证据。

**时间预算**：A 约 4 小时，B 约 5 小时，C 约 5 小时，周期两周。

## 四、与 nano-ollama 的衔接

如果用 nano-ollama 作为贯穿全课程的项目，本讲的实验就是它的第一层。
衔接靠三样东西：一份从第一周就固定下来的头文件 `nano.h`；每一层都有助教提供的
参考二进制；以及每一讲最后一页把该讲的知识点映射到该层的一个硬接触点。

| 层 | 对应讲次 | 学生实现 | 由上一层得到 | 交给下一层 |
| --- | --- | --- | --- | --- |
| L1 | 数据的表示 | `gguf-lens`、`dequantize` | 一个 `.gguf` 文件 | `nano_model_load()`，内存里的权重与形状 |
| L2 | 机器级程序 | `matmul` / `dot` 的 x86-64 与 SIMD 实现，并读编译器的汇编 | L1 的权重 | 一次前向所需的全部算子 |
| L3 | 存储层次与性能 | 分块、访存量估算、`perf` 测量，预测→测量→解释 | L2 的算子 | 一份性能报告与优化后的算子 |
| L4 | 链接与动态加载 | 算子编成 `.so`，运行时按 CPU 特性选择；实现最小的符号解析 | L3 的算子 | 可插拔的算子后端 |
| L5 | 进程、虚拟内存与 I/O | `mmap` 加载权重、观察页缓存、提供一个 HTTP 端点 | L4 的后端 | 一次完整的 completion |

关键的设计约束有三条：

1. **接口先于实现固定**。`nano.h` 在第一周发布，之后只增不改。学生在 L1 交的是
   一个符合该头文件的实现，L2 的测试直接链接它。
2. **每层配一份参考实现**。某一层没做完的学生用参考二进制继续下一层，
   一次失败不会级联到整个学期。
3. **每层都保留读字节的成分**。L2 读指令编码，L3 读缓存行与访存量，
   L4 读 ELF 的节与重定位，L5 读 `/proc/<pid>/smaps`。工程量增加的同时，
   底层机制始终是被考核的对象。

L1 与 L2 之间的接口是这套安排里最具体的一处：L2 的 `matmul` 吃的正是
L1 的 `dequantize` 输出的浮点数组，学生在 L1 把 Q4_0 解错，L2 的测试立刻不过。

## 五、不采用 nano-ollama 时的备选：取证型实验 `gguf-recov`

如果不做贯穿全课程的项目，本讲可以单独出一个取证型实验，创新点在于**裁决由系统
本身完成，无法伪造**。

给学生一个被破坏的 `.gguf`，破坏方式限定在本讲讲过的范围内：

- 文件尾部被截断，最后一个张量不完整；
- `version` 字段按大端写入；
- 某个张量的 `d` 全部乘了 2，反量化结果整体偏大；
- 张量数据区某一段被逐字节取反；
- 对齐填充被删除，此后所有偏移前移。

要求修复到 `nano-run model.gguf "1+1="` 输出固定的答案。模型答对即为修复成功，
提交任何形式的报告都不能替代这一条。学生必须从模型的输出行为反推到具体的字节，
这条推理链跨越了从应用到表示的全部层次。

难度分布不均是这个实验的风险，因此配一套分级线索：每取一条线索扣固定分数，
线索从「问题出在哪一类字段」逐级细化到「问题出在哪个偏移」。

**对抗变体**：两人一组，A 破坏一份 `.gguf`，限定只能改动不超过 64 字节且模型仍能加载，
B 负责恢复。双向评分，破坏得越隐蔽、恢复得越快，两人分数都越高。

**建议**：把 `gguf-recov` 作为 Lab 1 的附加题，而不是必做部分。它的
不可伪造性和跨层推理是其他类型的实验给不出的，但它的调试成本不适合作为
全班的必修路径。

## 六、给助教的实现清单

- 扩展 `examples/make_gguf.py`，生成 `small.gguf` 与五个损坏样本，参数写进脚本，可复现；
- 五个 bug 版本从同一份参考实现打补丁生成，保证每个版本只差一处；
- 自动测试四项：账目精确相等、误差上界、穷举等价、逐字节比对；
- 抽签脚本，种子公开，抽签结果全班可自行验证；
- 参考实现 `nano.h` 与 L1 的参考二进制，与实验同时发布。
