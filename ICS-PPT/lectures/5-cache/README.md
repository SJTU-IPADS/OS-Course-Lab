# ICS · 局部性与缓存

独立的一讲：从 `sum_rows` 与 `sum_cols` 对同一矩阵求和的效率差异出发，提出相同工作量为何有不同运行时间的问题，用局部性与存储器层次结构解释这一现象，再讲缓存模型及其访问、写策略与性能指标，把这些用到程序的编写上，最后以大模型推理中的 KV Cache 为例说明软件缓存的容量、访存与分配。素材来自 `lectures/ICS2/2-6-locality`（局部性）与 `2-7-cache`（缓存）。前置知识是第一至第五讲（数据表示、汇编、CPU、GPU）。虚拟内存尚未讲授，本讲不出现虚拟地址、地址翻译、页表与 TLB。

中文是基线（写在 Python 里），英文是 `i18n/en.toml` 翻译覆盖层。

## 结构

封面之后直接分五个部分，每部分以一页 `lecture.bridge(...)` 开头，只写「第 x 部分：标题」；该部分的起点问题写在 `pages.py` 中该部分开头的注释里；第二部分以「练习与小结」小节结束（题目一页，答案一页或几页，需要逐次说明的答案是动画，题面重复在答案之上），第三、四、五部分按内容分小节：第三部分为缓存副本的一致性、写 hit、写 miss、性能指标与设计参数，第四部分为缓存友好的规则、矩阵乘法的循环顺序、存储器山，第五部分为相亲节目、大模型的文本生成与注意力、KV Cache、显存中的 KV Cache 管理。小节只出现在目录中，不另加过渡页。共 177 张幻灯片，其中有 31 组动画（`p.frames`），每帧一张。

贯穿全讲的程序是按行存放的矩阵 `W[M][N]`。第一部分先展示 `sum_rows` 与 `sum_cols`，代码下方各有一张静态矩阵图，用由浅到深的颜色表示遍历顺序。问题页 `rowcol-question` 的上部与代码比较页完全相同，只把末行改为「两种矩阵的求和方式是否会存在运行时间的差异？」。随后实测两者的运行时间，再给出两种矩阵遍历的访问模式。「空间局部性与缓存」说明软硬件设计者如何利用空间局部性：把访问的数据及其邻近数据放在更快的存储中，使后续对邻近数据的访问可以直接从缓存读取。随后用 CPU、缓存与内存的具体模型说明硬件组织。`cache-features` 保留硬件模型页的全部内容，在图下补充按块取入与放置、替换策略：即使只需一个字节，也会取入整个块，提前取得邻近字节。放置策略规定新块的候选位置，替换策略在候选位置无空位时决定逐出哪个旧块。随后说明 hit 与 miss，再逐次执行两种遍历，定义 miss 率并解释实测时间差异的方向。第二部分以 CPU、缓存与内存模型开始，`cache-model` 完整复用 `cache-between` 的内容。随后给出最直接的缓存：每一项保存完整的地址与数据，查找时逐项比较，一半的存储保存地址，查找要比较全部的项。组、行与块的组织回答这两个缺陷：一个标记对应 $B$ 字节的块，地址的一部分位直接选出一组。块偏移取地址的最低位，一个块是内存中连续的字节。之后再说明缓存怎样判断 hit，并从直接映射的行利用率引出全相联与组相联，末尾的「练习与小结」用矩阵求和练习分析地址划分与两种遍历的 miss 率，再讨论缓存设计的取舍与缓存、预取的广泛应用。第三部分从 Copy Fail 新闻引出写入与副本一致性，用单缓存模型说明写策略和性能指标，第四部分改写程序。第五部分自成一线，先立一个相亲节目的情景：第一页给出节目的四条要求，问节目组按怎样的流程决定嘉宾入场的顺序。四条要求对应大模型生成文本的特点：嘉宾一位接一位地入场，对应 token 逐个生成并接在输入末尾。节目组只能从每位嘉宾自己的介绍里得知相关的信息，对应每个 token 的查询、键与值只由它自己的向量算出。下一位嘉宾要同时与上一位嘉宾以及已经入场的全部嘉宾关联紧密，使相邻的切换与整场节目都不突兀，对应下一个 token 由最后一个 token 的向量加上它的注意力输出预测。每位嘉宾入场后，节目组要尽快决定下一位嘉宾，对应解码的每一步只为新 token 计算，已有 token 的键与值存入缓存。节目组事先不知道嘉宾的特点与兴趣，对应 token 之间的关系由 token 的内容在运行时算出。第二页给出整个流程（入场、介绍、阅读、邀请），嘉宾之间不交流，阅读与邀请都由节目组完成，之后用具体例子逐页展开。嘉宾由个人资料得出特点、价值与兴趣，入场后介绍自己。之后的每次阅读用的是新嘉宾的兴趣，所以节目组在纸条上记录特点与价值，一位嘉宾的兴趣只在这位嘉宾入场时使用。新嘉宾入场后，节目组按新嘉宾的兴趣对照每张纸条上的特点（包括新嘉宾自己的）得到注意程度，结论是价值按注意程度加权平均。下一位嘉宾要同时与上一位嘉宾以及已经入场的全部嘉宾关联紧密，所以节目组把最后入场的嘉宾的资料与结论合起来，与候场名单比对后邀请得分最高的一位。新嘉宾入场时节目组已有的纸条不变，先入场嘉宾的兴趣不再使用，节目组不必请先入场的嘉宾重新介绍，所以能尽快决定下一位嘉宾。随后用一串问题把情景对应到模型：模型逐个输出 token，字符编码的远近与含义无关，所以 token 嵌入为向量（嘉宾的资料），向量乘以三个权重矩阵得到查询、键与值（兴趣、特点与价值），这种查找称为注意力。只考虑一层注意力时，最后一个 token 的向量加上它的输出，经输出层得到下一个 token 的概率。然后用矩阵画出注意力，指出解码一步只多出新 token 的一行，而已有 token 的 k、v 不变，由此说明 KV Cache 缓存的是哪部分、为什么缓存，再讨论显存不足时先按淘汰策略选出让出显存的会话，然后讨论被淘汰的缓存放到哪里：与硬件缓存一样换出到内存或 SSD、按需换入，或者利用 KV Cache 由计算得出这一点直接失效、按需重算，系统选择更快的一种。

## 缓存分析的模型与验证

第二部分的「练习与小结」使用 `int W[512][512]`，元素 4 字节，基址 `0x0000000100000000` 按 4 KiB 对齐。题设采用硬件查询得到的 48 KiB、64 组、12 路、64 字节块，规定 64 位字节地址、组索引取中间位与 LRU 替换。每个函数均从空缓存开始，只统计 W 的读取，无其他访存流量，不额外预取其他块。第 1 题给出简单算式：$S=(48\times1024)/(12\times64)=64$，$b=\log_2 64=6$，$s=\log_2 64=6$，$t=64-6-6=52$，每块包含 $64/4=16$ 个 `int`。

| 函数 | 矩阵读取次数 | miss 次数 | miss 率 |
| --- | --- | --- | --- |
| `sum_rows` | 262,144 | 16,384 | 6.25% |
| `sum_cols` | 262,144 | 262,144 | 100% |

第 2 题从每行 $512\times4/64=32$ 个块出发，整个矩阵共有 $512\times32=16,384$ 个块。按行连续读取同一块中的 16 个元素，每块只有首次读取发生 miss。按列每次跨过 32 块，组号在两组间交替，第一列为组 0、32，每组涉及 256 个块，而每组只有 12 行。同一块复用前已有 255 个其他同组块被读取，LRU 已将它逐出，因此按列的所有读取均 miss。一列的 512 个块共 32 KiB，低于缓存的 48 KiB，冲突来自固定的组映射。开头实测使用 4096 × 4096 矩阵，练习使用 512 × 512 矩阵。模型的 miss 率解释按行更快的方向，不能直接换算为约 18 倍的实测运行时间比。

`examples/rowcol_cache_model.py` 用标准库模拟 LRU，生成上述两组计数与题设参数，输出为 `examples/rowcol_cache_model.json`。按列逐次模拟所有矩阵读取，按行合并连续的同块引用，并用小规模逐次读取交叉验证等价性。页源与图源只读取 JSON，导入与渲染时均不运行全量模拟。生成命令见构建一节，省略 `--out` 时输出 JSON 到标准输出。

## 动画

逐步发生的过程用 `p.frames` 展开成帧，用相邻帧展示关键步骤：CPU、缓存与内存之间的 hit/miss 访问、步长为 1 与步长为 k 的访问、直接映射的访问、全相联的标记比较、组相联的访问与替换、矩阵求和练习的按列读取与替换、写入的一致性问题、写 hit 与写 miss 的两种策略（一个动画一种策略，不并排）、矩阵乘法三类循环顺序的内层迭代（只画第 1、2、8 次迭代）、相亲节目的流程、纸条的阅读、邀请与新嘉宾入场、文本生成的预填充与解码两步、查询与键的内积到值的加权和、注意力的三步与无缓存、有缓存时的解码一步，以及显存溢出、换出与换入、缓存失效与重新计算（第五部分）。每个动画是 `diagrams/` 下的脚本生成的一组 `assets/<名>-N.svg`，hit、miss、LRU 状态与 miss 次数都由脚本中的模拟算出，页面文字中的数字与图一致。帧前的文字每帧都显示，帧后的文字只在最后一帧出现。

## 约定

- hit/miss：正文、标题、讲稿与图中的缓存访问结果统一写作 `hit` 与 `miss`。复合术语写作「冷 miss」「冲突 miss」「容量 miss」「写 hit」「写 miss」「hit 率」「miss 率」。
- 术语：缓存、hit、miss、块、行、组、有效位、标记、组索引、块偏移、冷 miss、冲突 miss、容量 miss、写直达、写回、写分配、非写分配。
- 用词：memory 与 main memory 都写「内存」，cache 写「缓存」，与其他各讲一致。「存储器」只用于把缓存、SSD 与磁盘包括在内的定名：存储器层次结构、存储器山，以及随机访问存储器（RAM）。
- 记号：地址 $m$ 位，$S = 2^s$ 个组，每组 $E$ 行，块 $B = 2^b$ 字节，标记 $t = m - s - b$ 位，容量 $C = S \times E \times B$（只计数据）；常用划分中，地址从高位到低位依次是标记、组索引、块偏移。
- 不引用其他讲；术语在第一次出现处用一句话说明；页面不命名运行演示的机器，涉及硬件的示例取当前产品的参数。
- 练习答案由程序模拟得出，算法写在答案页的讲稿中。
- 代码页中的注释是英文，不翻译。
- 英文版只同步译文，不核对排版。
